# Граф зависимостей и влияние изменений

## Состав

- [diff](../../src/graph/diff.codelore.md) — Преобразует строку unified diff в структурированный список файлов с указанием затронутых диапазонов строк для последующего анализа изменений в проекте.
- [domain-dag](../../src/graph/domain-dag.codelore.md) — Превращает граф зависимостей между файлами в граф зависимостей между доменами, сопоставляя каждый файл его домену через fileToDomain.
- [file-dag](../../src/graph/file-dag.codelore.md#file-dagts) — Превращает индекс сущностей проекта в файловый граф зависимостей и раскладывает выбранные файлы по волнам генерации, где каждая волна содержит группы файлов, которые можно документировать одновременно, потому что все их зависимости лежат в более нижних волнах.
- [impact](../../src/graph/impact.codelore.md) — Вычисляет множество секций, затронутых изменением переданных сущностей, объединяя прямое и транзитивное влияние.
- [waves](../../src/graph/waves.codelore.md#wavests) — The module turns a file dependency graph into ordered waves of entities, supporting two grouping strategies — by dependency depth and by strongly connected components — and provides the underlying strongly-connected-component extraction used by one of them.

## Зачем это нужно

Подсистема определяет, какие секции документации нужно пересобрать при изменении исходного кода, и в каком порядке обрабатывать файлы. Для этого она разбирает unified diff, строит файловый граф зависимостей и вычисляет затронутые секции по именам сущностей. Генератор документации использует её, чтобы пересобирать только изменившиеся фрагменты снизу вверх, избегая полной регенерации.

## Что делает

Подсистема парсит unified diff в список изменённых файлов с ханками и диапазонами строк. По сущностному индексу строит файловый граф зависимостей, отбрасывая самоссылки и файлы вне индекса. Затем раскладывает выбранные файлы по волнам генерации: каждая волна содержит группы файлов, все зависимости которых лежат в более ранних волнах. По списку имён сущностей находит прямо затронутые секции (через owns/depends) и рекурсивно добавляет секции, зависящие от них, возвращая отсортированный результат с минимальным порядком.

## От чего зависит

Подсистема полагается на внешний индекс сущностей, который предоставляет отображение файлов на сущности, прямые зависимости и использования сущностей, а также информацию о том, какие секции владеют сущностями или зависят от них. Она не обращается к файловой системе, не разбирает исходный код напрямую и не генерирует документацию. Индекс должен быть актуален; подсистема не проверяет его корректность. Также она не определяет, какие сущности изменились по диффу — это делает вызывающий код.

## Кто и как использует

Вызывающий код передаёт unified diff в parseUnifiedDiff и получает список изменённых файлов с ханками. Затем он самостоятельно сопоставляет строки с сущностями индекса и вызывает getAffectedSectionsForEntities, передавая имена сущностей и индекс; функция возвращает отсортированный список затронутых секций. Независимо от диффа, вызывающий код может запросить волны генерации для любого набора файлов: generationWaves строит файловый DAG через buildFileDag, фильтрует файлы, присутствующие в графе, и возвращает группы файлов, готовые к документированию снизу вверх.

## Чего не делает

Парсер ожидает строгий unified diff, обрабатывает файлы по одному и не поддерживает многородительские диффы. Файловый DAG игнорирует сущности, отсутствующие в индексе, и зависимости внутри одного файла, что может скрыть часть связей. Индекс сущностей должен быть актуален, иначе результаты неверны.
