## Зачем это нужно

Хранилище состояния документации получает готовое JSON-состояние документа и сохраняет его на диск вместе с Markdown-файлом и переводами, гарантируя целостность данных при сбоях за счёт атомарной записи (временный файл с последующим переименованием). Остальной системе оно позволяет передать состояние и забыть о деталях — не нужно беспокоиться о безопасной записи, согласованности JSON и Markdown или удалении устаревших переводов.

## Что делает

Подсистема владеет полным циклом сохранения документа. Сначала атомарно записывает JSON-состояние в `<indexDir>/state/`. Затем вызывает `renderDoc` (подсистема рендеринга), чтобы получить Markdown-представление, и атомарно сохраняет его. Для каждого языка из `config.docs.translations` через `translationDocPath` вычисляет путь и генерирует переведённый Markdown-файл; после этого `cleanupTranslationFiles` удаляет переводные файлы, у которых нет актуального состояния. При изменении конфигурации `reapplyConfigToAllDocs` перебирает все сохранённые документы, с помощью `computeConfigFingerprint` сравнивает отпечатки конфигурации и перерендеривает только те, где отпечаток изменился.

## От чего зависит

Хранилище не формирует Markdown-разметку: за локализованные заголовки, группировку устаревших блоков и общее форматирование отвечает подсистема рендеринга. Хранилище лишь передаёт состояние документа через `renderDoc` и получает готовый текст. Самостоятельно не принимает решение, какие блоки отображать — это делает `applyRenderDecision`, которая используется подсистемой рендеринга. Внутреннее хеширование конфигурации выполняет `computeConfigFingerprint`, но сам отпечаток вычисляется в рамках этого же модуля, поэтому зависимость внешняя только от рендеринга.

## Кто и как использует

При поступлении состояния документа: 1) JSON-файл атомарно записывается в `<indexDir>/state/`. 2) Вызывается `renderDoc`, полученный Markdown атомарно сохраняется. 3) Для каждого языка из `config.docs.translations` с помощью `translationDocPath` вычисляется путь, генерируется переведённый Markdown-файл (тоже атомарно). 4) `cleanupTranslationFiles` удаляет переводные файлы, для которых нет состояния. При вызове `reapplyConfigToAllDocs`: для каждого сохранённого состояния вычисляется отпечаток `computeConfigFingerprint`; если он отличается от предыдущего — документ перерендеривается, иначе пропускается.
