# Перевод документации

## Состав

- [translator](../../src/llm/translator.codelore.md) — Создаёт уникальный строковый ключ для пары идентификаторов раздела и блока, чтобы использовать его в качестве ключа ассоциативного массива при фингерпринтинге переводов.

**Зависит от:** [Единый формат ошибок](error-handling.codelore.md#единый-формат-ошибок) · [Разбор JSON-ответов LLM с повтором запроса](llm-json-response-parsing.codelore.md#разбор-json-ответов-llm-с-повтором-запроса)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore)

## Зачем это нужно

Подсистема переводит канонические тела блоков документации на заданный язык через LLM-провайдера, гарантируя сохранность кодовых промежутков и отсутствие нетранслированного эха исходного текста. Остальная система получает карту только качественных переводов — блоки с дефектами отбрасываются, что позволяет вызывающему коду опираться на готовый результат без дополнительной валидации.

## Что делает

Подсистема владеет полным циклом перевода блоков документации. translateBlocks принимает входные блоки с идентификаторами раздела и блока, строит промпт для LLM через buildTranslateRequest и получает ответ через completeAndParseTranslation — этот вызов автоматически обрабатывает невалидный JSON повторами запроса, возвращая либо структурированный объект, либо ошибку INVALID_LLM_RESPONSE. Затем collectViolations проверяет каждый переведённый блок на наличие в ответе, целостность кодовых промежутков и отсутствие нетранслированного текста. При нарушениях для проблемных блоков формируется ремонтный запрос buildRepairRequest, ответ на который снова проверяется. Финальный вызов blockViolation отсеивает оставшиеся дефектные переводы, и наружу возвращается карта только качественных переводов. translationNeedsWork позволяет вызывающему коду проверить сохранённый перевод на дефекты, делегируя проверку той же функции blockViolation.

## От чего зависит

Подсистема опирается на два внешних сервиса. Разбор JSON-ответов LLM с повтором запроса берёт на себя извлечение структурированного объекта из текстового ответа модели: исправляет Markdown-фенсы и другие артефакты, а при неудаче повторяет запрос к модели с объяснением ошибки. translateBlocks вызывает completeAndParseTranslation, которая внутри использует этот механизм, и получает либо готовый объект, либо CodeloreError с кодом INVALID_LLM_RESPONSE — собственная логика повторов для невалидного JSON подсистеме не нужна. Единый формат ошибок гарантирует, что наружу из completeAndParseTranslation уходит предсказуемая структура CodeloreErrorPayload с машиночитаемым кодом, на которую может положиться вызывающий код.

## Кто и как использует

Входные блоки с идентификаторами раздела и блока передаются в translateBlocks. Функция buildTranslateRequest формирует промпт для LLM, completeAndParseTranslation отправляет его и через подсистему разбора JSON получает структурированный ответ, повторяя запрос при невалидном JSON. Затем collectViolations проверяет каждый переведённый блок на наличие, целостность кодовых промежутков и отсутствие нетранслированного текста. При нарушениях для проблемных блоков собирается ремонтный запрос buildRepairRequest — остальные блоки не перезапрашиваются. Ответ на ремонтный запрос снова проходит проверку. Финальный вызов blockViolation отсеивает оставшиеся дефектные переводы, и на выходе возвращается карта только качественных переводов.

## Чего не делает

Подсистема не проверяет семантическую точность перевода — контроль ограничен формальными признаками: целостность кодовых промежутков и отсутствие нетранслированного эха исходного текста. Блоки, не прошедшие финальную проверку blockViolation, отбрасываются без уведомления, поэтому вызывающий код должен самостоятельно обрабатывать ситуацию отсутствия перевода. Подсистема работает только с текстовым содержимым блоков: не управляет языковыми настройками, не сохраняет переводы на диск и не взаимодействует с пользовательским интерфейсом.
