# Перевод документации

## Состав

- [translator](../../src/llm/translator.codelore.md) — Создаёт уникальный строковый ключ для пары идентификаторов раздела и блока, чтобы использовать его в качестве ключа ассоциативного массива при фингерпринтинге переводов.
- [doc-paths](../../src/markdown/doc-paths.codelore.md) — Строит путь файла перевода для документа, вставляя код языка в имя файла так, чтобы перевод сохранялся рядом с оригиналом и имел предсказуемое имя.

**Зависит от:** [Единый формат ошибок](error-handling.codelore.md#единый-формат-ошибок) · [Разбор JSON-ответов LLM с повтором запроса](llm-json-response-parsing.codelore.md#разбор-json-ответов-llm-с-повтором-запроса)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore) · [Хранилище состояния документации](doc-state-storage.codelore.md#хранилище-состояния-документации) · [Рендеринг и локализация Markdown-документов](markdown-rendering.codelore.md#рендеринг-и-локализация-markdown-документов)

## Зачем это нужно

Переводит канонические тела блоков документации на другие языки через LLM, сохраняя кодовые вставки и отслеживая устаревшие переводы.

## Что делает

Строит запрос к LLM для перевода всех блоков документа, извлекает ответ с повторными попытками при невалидном JSON, выявляет нарушения (отсутствие блока, несовпадение кодовых промежутков, нетранслированный текст) и отправляет ремонтный запрос только для проблемных блоков. Финальная проверка отбрасывает блоки, не прошедшие проверку или отсутствующие после ремонта. Также проверяет, содержит ли сохранённый перевод дефект, требующий перевода заново.

## От чего зависит

Зависит от подсистемы разбора JSON-ответов LLM с повтором запроса для получения структурированного JSON из текстового ответа модели и от подсистемы единого формата ошибок. Сама не занимается построением путей файлов переводов — для этого использует функцию из [src/markdown/doc-paths.ts](../../src/markdown/doc-paths.codelore.md), которая вставляет код языка в имя файла.

## Кто и как использует

Вызов translateBlocks передаёт все блоки документа в buildTranslateRequest, затем completeAndParseTranslation извлекает ответ с повторными попытками при невалидном JSON. После этого collectViolations проверяет каждый блок на отсутствие в ответе, несовпадение кодовых промежутков и нетранслированный текст. При нарушениях отправляется buildRepairRequest только для проблемных блоков. Финальная проверка blockViolation отбрасывает блоки, не прошедшие проверку или отсутствующие после ремонта. Для проверки сохранённого перевода translationNeedsWork делегирует проверку той же blockViolation.

## Чего не делает

Не переводит весь документ целиком — только канонические тела блоков. Не сохраняет и не загружает переводы на диск — это делают другие подсистемы. Не обрабатывает ошибки провайдера LLM — они пробрасываются наружу. Не гарантирует, что все блоки будут переведены: блоки, не прошедшие финальную проверку или отсутствующие после ремонта, отбрасываются.
