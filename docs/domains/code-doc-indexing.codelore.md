## Зачем это нужно

Подсистема строит и поддерживает два независимых индекса (кодовый и документационный), обеспечивая системе быстрый поиск сущностей и секций документации по идентификатору, файлу или сущности. Кодовый индекс отображает файлы на экспортированные сущности с их зависимостями, а документационный — загружает состояния из хранилища и создаёт обратные карты для поиска. Системе не нужно обращаться к файловой системе или хранилищу состояний при каждом запросе.

## Что делает

Подсистема отвечает за построение и актуальное состояние обоих индексов. Индекс кода строится обходом файлов, попадающих под sourceGlobs и scope: для каждой экспортированной сущности фиксируются идентификатор, прямые зависимости и документационные метаданные (которые предоставляет анализатор метрик). Индекс документации загружает все состояния через DocStateStorage, преобразует их в секции и заполняет обратные карты fileToSections и entityToSections с детерминированной сортировкой. Для инкрементального обновления patchDocIndexPaths удаляет секции по переданным путям, очищает привязки в entityToSections и добавляет секции из свежих состояний.

## От чего зависит

Подсистема делегирует вычисление веса сущности и решение о документировании анализатору метрик — эти данные попадают в документационные метаданные индекса кода и в поле weight секций документации. Для чтения состояний документации использует DocStateStorage. Нормализацию путей и кодирование идентификаторов выполняет через низкоуровневые утилиты. Не преобразует состояния в Markdown, не разрешает реэкспорты, не проверяет целостность связей — эти задачи лежат на вызывающей стороне или других подсистемах.

## Кто и как использует

При полной перестройке buildCodeIndex принимает sourceGlobs и scope, обходит файлы и строит отображение файл→список сущностей с их атрибутами. Одновременно buildDocIndex загружает все состояния через DocStateStorage, преобразует их в секции и наполняет обратные карты fileToSections и entityToSections, сортируя ключи для воспроизводимости. При инкрементальном обновлении patchDocIndexPaths: из принятого DocIndex удаляются секции для переданных docPaths и очищаются записи в entityToSections; затем для каждого пути загружается актуальное состояние, добавляются новые секции, сортируются списки затронутых сущностей и обновляется метка generatedAt.

## Чего не делает

Индексатор кода не прослеживает реэкспорты через export * from — зависимость считается с файлом реэкспорта, а не с фактическим источником. Неэкспортированные сущности и файлы вне sourceGlobs (если не попали в scope) игнорируются. Индексатор документации не проверяет целостность перекрёстных ссылок, не записывает изменения на диск и не изменяет состояния документов — строит индекс только из прочитанных состояний. При инкрементальном обновлении сортируются только списки сущностей для затронутых документов; порядок в остальных сущностях не переопределяется.
