## Состав

- [domain-map](../../src/domains/domain-map.codelore.md#domain-mapts) — This file exists to translate file paths into domain identifiers and to determine which domains are covered by a set of files, so that downstream indexing can group entities by domain.
- [code-indexer](../../src/indexer/code-indexer.codelore.md) — Построение полного индекса кода проекта: отображение всех файлов и экспортированных сущностей с их прямыми зависимостями и документационными метаданными.
- [domain-entities](../../src/indexer/domain-entities.codelore.md#domain-entitiests) — Файл предоставляет набор функций и констант для работы с доменными сущностями индексатора, используемых другими модулями пакета.

## Зачем это нужно

Подсистема строит и поддерживает два независимых индекса — кодовый и документационный — и на их основе создаёт доменные сущности и карту покрытия. Благодаря этому остальная система ищет сущности и секции документации по идентификатору, файлу или сущности, не обращаясь каждый раз к файловой системе или хранилищу состояний.

## Что делает

Подсистема строит кодовый индекс через buildCodeIndex: обходит файлы, попадающие под sourceGlobs и scope, и для каждой экспортированной сущности фиксирует идентификатор, прямые зависимости и документационные метаданные. Документационный индекс строит buildDocIndex: загружает все состояния через DocStateStorage, преобразует их в секции и заполняет обратные карты fileToSections и entityToSections с детерминированной сортировкой. Инкрементальное обновление выполняет patchDocIndexPaths: удаляет секции для переданных путей, очищает привязки в entityToSections, загружает свежие состояния и добавляет секции заново, сортируя только затронутые списки. Дополнительно buildDomainEntities создаёт синтетические сущности для доменов и проекта на основе CodeIndex и DomainMap, а domainCoverage проверяет покрытие файлов доменами, выявляя uncovered, doubleAssigned и danglingFiles.

## От чего зависит

Подсистема полагается на DocStateStorage для чтения состояний документации, на анализатор метрик для вычисления веса сущностей и решений о документировании, и на низкоуровневые утилиты для нормализации путей и кодирования идентификаторов. Она не преобразует состояния в Markdown, не разрешает реэкспорты и не проверяет целостность связей — эти задачи остаются на вызывающей стороне или других подсистемах.

## Кто и как использует

При полной перестройке buildCodeIndex принимает sourceGlobs и scope, обходит файлы и строит отображение файл→список экспортированных сущностей с их атрибутами. Параллельно buildDocIndex загружает все состояния через DocStateStorage, преобразует их в секции и наполняет обратные карты fileToSections и entityToSections, сортируя ключи для воспроизводимости. Затем buildDomainEntities использует CodeIndex и DomainMap, чтобы создать синтетические сущности для доменов и проекта, а domainCoverage проверяет, какие документированные файлы остались без домена, попали в несколько доменов или висят без файла. При инкрементальном обновлении patchDocIndexPaths удаляет секции для переданных docPaths, очищает привязки в entityToSections, загружает актуальные состояния и добавляет секции заново, сортируя только списки затронутых сущностей и обновляя generatedAt.

## Чего не делает

Индексатор кода не прослеживает реэкспорты через export * from — зависимость считается с файлом реэкспорта, а не с фактическим источником. Неэкспортированные сущности и файлы вне sourceGlobs (если не попали в scope) игнорируются. Индексатор документации не проверяет целостность перекрёстных ссылок, не записывает изменения на диск и не изменяет состояния документов — строит индекс только из прочитанных состояний. При инкрементальном обновлении сортируются только списки сущностей для затронутых документов; порядок в остальных сущностях не переопределяется. domainCoverage может сообщить о файлах без домена, файлах с несколькими доменами и висящих файлах — вызывающая сторона должна решать, как на это реагировать.
