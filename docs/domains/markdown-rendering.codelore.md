# Рендеринг и локализация Markdown-документов

## Состав

- [callouts](../../src/markdown/callouts.codelore.md) — Обеспечивает единообразное отображение уведомлений об устаревших блоках в виде маркдаун-цитаты, используя локализованные шаблоны из localeBundle.
- [linkify](../../src/markdown/linkify.codelore.md#linkifyts) — Преобразует ссылки вида file: в абсолютные пути, чтобы они корректно работали в сгенерированной документации, и оставляет все остальные ссылки без изменений.
- [locales](../../src/markdown/locales.codelore.md) — Предоставляет локализованный набор строк (заголовки, причины, подсказки) для указанного языка, используя английский как запасной вариант.
- [render-doc](../../src/markdown/render-doc.codelore.md) — Собирает итоговый Markdown-документ из отрендеренных секций, формируя для каждой контекст ссылок и навигационную строку для доменных секций, а при пустом списке секций возвращает пустую строку.

## Зачем это нужно

Подсистема собирает итоговый Markdown-документ из секций и блоков, вставляя локализованные заголовки и цитаты об устаревших или ещё не переведённых блоках. Она не требует от остальной системы разбираться в структуре секций и статусах блоков — вызывающий код просто передаёт state, config и language.

## Что делает

renderDoc обходит секции в порядке sectionOrder, для каждой строит linkContext с целями символов и путей, а для доменных и проектных секций дополнительно формирует навигационную строку tierLead. Затем каждая секция передаётся в renderSection, которая определяет язык перевода, выбирает заголовки блоков (локализованные или канонические), группирует устаревшие блоки по staleReason и staleSince в Map и выводит перед свежими блоками один staleCalloutText на группу. Для свежих блоков выводит подзаголовок и тело; если перевод отсутствует или устарел, blockBody вставляет translationPendingCallout вместо тела. Итоговые Markdown всех секций склеиваются двойным переводом строки, добавляется завершающий \n.

## От чего зависит

Подсистема полагается на модуль «Отпечатки блоков документации» для получения признаков staleSince и staleReason. Сама она не вычисляет хеши и не управляет синхронизацией переводов — только трансформирует готовые метки устаревания в цитаты. Если нужна новая локализация, статический реестр LOCALES требуется дополнить вручную; подсистема сама не обновляет реестр.

## Кто и как использует

Вызов renderDoc получает state, config и language. Если sectionOrder пуст — немедленный возврат пустой строки. Иначе для каждой секции из sectionOrder формируется linkContext (с помощью buildPathTargets, sectionLinkTargets и buildEntityLinkMap из linkify.ts), а для секций, определяемых через isTierSection, дополнительно строится tierLead. Каждая секция передаётся в renderSection, которая определяет язык перевода, выбирает заголовки блоков (локализованные через resolveBlockHeadings или канонические), формирует заголовок с уровнем вложенности section.depth. Блоки проверяются на наличие и флаг rendered: отсутствующие и неотрендеренные пропускаются. Блоки с staleSince группируются в Map по ключу staleReason + staleSince и выводятся одним staleCalloutText на группу. Свежие блоки выводятся с подзаголовком и телом; при отсутствии или устаревании перевода blockBody вставляет translationPendingCallout. Итоговые Markdown всех секций склеиваются двойным переводом строки, добавляется завершающий \n.
