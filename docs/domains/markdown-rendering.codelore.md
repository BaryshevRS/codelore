# Рендеринг и локализация Markdown-документов

## Состав

- [callouts](../../src/markdown/callouts.codelore.md) — Обеспечивает единообразное отображение уведомлений об устаревших блоках в виде маркдаун-цитаты, используя локализованные шаблоны из localeBundle.
- [linkify](../../src/markdown/linkify.codelore.md#linkifyts) — Преобразует ссылки вида file: в абсолютные пути, чтобы они корректно работали в сгенерированной документации, и оставляет все остальные ссылки без изменений.
- [locales](../../src/markdown/locales.codelore.md) — Предоставляет локализованный набор строк (заголовки, причины, подсказки) для указанного языка, используя английский как запасной вариант.
- [render-doc](../../src/markdown/render-doc.codelore.md) — Собирает итоговый Markdown-документ из отрендеренных секций, формируя для каждой контекст ссылок и навигационную строку для доменных секций, а при пустом списке секций возвращает пустую строку.

**Зависит от:** [Отпечатки блоков документации](block-fingerprinting.codelore.md#отпечатки-блоков-документации) · [Перевод документации](doc-translation.codelore.md#перевод-документации)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore) · [Хранилище состояния документации](doc-state-storage.codelore.md#хранилище-состояния-документации) · [Конфигурация проекта](project-config.codelore.md#конфигурация-проекта)

## Зачем это нужно

Подсистема собирает итоговый Markdown-документ из секций и блоков, вставляя локализованные заголовки и цитаты об устаревших или ещё не переведённых блоках. Она не требует от остальной системы разбираться в структуре секций и статусах блоков — вызывающий код просто передаёт state, config и language.

## Что делает

Подсистема выбирает заголовки блоков в зависимости от языка перевода: для переводных языков берёт локализованные заголовки из config.docs.blockHeadingsByLanguage, иначе канонические из config.docs.blockHeadings. Она формирует заголовки секций с уровнем вложенности, добавляет сигнатуры и навигационные строки, группирует устаревшие блоки в сводный callout и вставляет цитаты о незавершённых переводах. Итоговые Markdown всех секций склеиваются двойным переводом строки, добавляется завершающий \n.

## От чего зависит

Подсистема полагается на две внешние подсистемы: «Отпечатки блоков документации» предоставляют стабильные отпечатки, по которым она определяет, устарел ли перевод блока, а «Перевод документации» поставляет канонические тела блоков и переведённые версии. Сама она не вычисляет отпечатки, не вызывает LLM и не управляет процессом перевода — она только потребляет готовые данные и собирает из них итоговый Markdown.

## Кто и как использует

Вызов renderDoc получает state, config и language. При пустом sectionOrder сразу возвращает пустую строку, не вычисляя контекст ссылок. Для каждой секции из sectionOrder строит linkContext с целями символов и путей, затем вызывает renderSection. В renderSection определяет язык перевода, выбирает заголовки блоков, формирует заголовок секции с уровнем вложенности и навигационной строкой. Для каждого блока из orderedRenderableBlocks проверяет наличие и флаг rendered: отсутствующие и неотрендеренные пропускаются. Устаревшие блоки группируются в сводный callout через callouts.ts, используя локализованные шаблоны из localeBundle. Итоговые Markdown всех секций склеиваются двойным переводом строки с завершающим \n.

## Чего не делает

Подсистема не работает с частично переведёнными блоками: блок либо свежий, либо устаревший, либо пропускается при rendered: false — промежуточных состояний нет. Она также не обрабатывает ссылки, не начинающиеся с file:, оставляя их без изменений, и не создаёт контекст ссылок при пустом списке секций, возвращая пустую строку.
