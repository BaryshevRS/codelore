# Пайплайн генерации документации файлов

## Состав

- [domain-pipeline](../../src/llm/domain-pipeline.codelore.md) — Generates a domain documentation for a single tier by writing blocks with retries, verifying them against member docs, and repairing contradicted blocks, returning the surviving blocks and the dropped ones.
- [file-chunks](../../src/llm/file-chunks.codelore.md) — Разбивает набор исходных файлов и секций документации на чанки, каждый из которых помещается в контекст одной LLM-генерации с учётом лимитов токенов и числа секций, заданных через WriterBudget.
- [file-pipeline](../../src/llm/file-pipeline.codelore.md) — Точка входа для LLM-генерации документации группы файлов: загружает контекст, разбивает на чанки, выполняет запросы с валидацией и ремонтом, собирает результат.
- [file-writer](../../src/llm/file-writer.codelore.md) — Упаковывает исходный код, секции документации и dependency docs в структурированный запрос для LLM.
- [generation-debug](../../src/llm/generation-debug.codelore.md) — Атомарная запись отладочного JSON-файла с данными о генерационном прогоне.

## Зачем это нужно

Подсистема за один прогон генерирует документацию для группы файлов (generateFileGroup) и для отдельного доменного уровня (generateDomainDoc). Она разбивает исходный код на чанки под лимиты модели, формирует и отправляет запросы, парсит ответы, проверяет каждый блок на фактические противоречия с помощью LLM и исправляет нарушения в цикле. Итоговый объект FileGenerationOutcome (для файлов) или набор блоков с отброшенными ID (для домена) содержит проверенные секции, готовые к сохранению — вызывающему не нужно повторять верификацию. За счёт этого остальная система получает надёжный инструмент сквозной регенерации документации, скрывающий детали лимитов модели и логики промптов.

## Что делает

Подсистема владеет полным циклом генерации документации: для файлов — загружает контекст, разбивает секции на чанки через planWriterChunks, параллельно обрабатывает каждый чанк (buildFileWriteRequest, parseFileWriteResponse, verifyChunkFacts с циклом ремонта), объединяет результаты, проверяет существующие блоки на соответствие зависимостям через verifyBlocksAgainstDeps и атомарно записывает отладочный снимок через writeGenerationDebug. Для домена — пишет блоки с повторными попытками через generateDomainDoc, верифицирует их по документации членов и исправляет противоречия. Утилита compactChunkCallers уменьшает дублирование тел вызывающих функций, отдавая приоритет вызывающим с runtimeEvidence — это оптимизирует размер промпта перед генерацией.

## От чего зависит

Пайплайн опирается на подсистему графа зависимостей для получения списка изменившихся файлов и секций, на конфигурацию проекта для бюджета токенов и терминов, на построение runtime-контекста для evidence вызывающих, и на подсистемы валидации для структурной и фактической проверки. При этом пайплайн самостоятельно строит граф прямых зависимостей через collectDependencyDocs (вызов buildFileDag) и выполняет структурную валидацию блоков в parseFileWriteResponse, а также исправляет нарушения детерминированной валидации через buildRepairRequest. Пайплайн не сохраняет документацию на диск — возвращает результат вызывающему фасаду. Он также не вычисляет начальный набор изменений — эту задачу решает подсистема графа зависимостей.

## Кто и как использует

Для файловой группы generateFileGroup загружает контекст секций и документацию зависимостей, разбивает секции на чанки через planWriterChunks, обрабатывает каждый чанк параллельно: buildFileWriteRequest строит запрос, parseFileWriteResponse разбирает ответ, verifyChunkFacts проверяет факты и при нарушениях запускает ремонт (buildRepairRequest) с повторной верификацией. Результаты чанков сливаются — более поздние чанки перезаписывают одноимённые блоки. Существующие блоки, не попавшие в генерацию, проходят проверку на соответствие документации зависимостей через verifyBlocksAgainstDeps. В конце writeGenerationDebug записывает отладочный снимок. Для доменного уровня generateDomainDoc пишет блоки с повторными попытками, верифицирует их по документации членов и исправляет противоречия, возвращая выжившие и отброшенные блоки.

## Чего не делает

Пайплайн не сохраняет сгенерированную документацию на диск — возвращает результат вызывающему. planWriterChunks разбивает файлы по границам top-level сущностей и не дробит отдельные сущности; если одна сущность превышает лимит токенов, она не будет разбита, и чанк может выйти за лимиты модели. collectDependencyDocs ограничивает суммарный объём документации зависимостей константами DEP_DOCS_TOTAL_CAP и DEP_DOC_FILE_CAP, молча отбрасывая данные сверх лимита. verifyBlocksAgainstDeps возвращает только идентификаторы секций без нарушений — вызывающий не узнает, какие блоки и в чём противоречат зависимостям. Ошибки файловой системы при записи отладочного снимка пробрасываются наверх без обработки.
