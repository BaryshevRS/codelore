# Общие низкоуровневые утилиты

## Состав

- [assign](../../src/domains/assign.codelore.md#assignts) — Модуль существует, чтобы изолировать два направления контракта API назначения: построение исходящего запроса и разбор входящего ответа.
- [hash](../../src/utils/hash.codelore.md) — Хеширует строку алгоритмом SHA-256 и возвращает 64-символьное hex-представление.
- [path](../../src/utils/path.codelore.md) — Нормализует разделители путей в стиле POSIX для кроссплатформенной совместимости.

## Зачем это нужно

Предоставляет набор чистых строковых операций, которые используют все остальные подсистемы: детерминированное SHA-256-хеширование, кроссплатформенную нормализацию путей, вычисление относительного пути от корня проекта, эвристическую фильтрацию путей и кодирование/декодирование идентификаторов для MCP-ресурсов. Ни одна функция не обращается к файловой системе и не имеет побочных эффектов — все расчёты выполняются только над переданными строками, что делает подсистему безопасной и предсказуемой для любого контекста вызова.

## Что делает

Хеширует любую строку SHA-256 через node:crypto (sha256). Нормализует обратные слеши в прямые (toPosixPath) и вычисляет относительный путь от корня проекта через resolve (relativeProjectPath) — обе операции только строковые, без доступа к диску или разрешения симлинков. Эвристически определяет, стоит ли исключить путь из индексации (isProbablyExcluded), по простым шаблонам строк — без glob или регулярных выражений. Кодирует (encodeResourceId) и декодирует (decodeResourceId) произвольные идентификаторы в URI-безопасную форму, не добавляя схему или префикс и не проверяя валидность входа.

## От чего зависит

Подсистема использует только встроенные модули Node.js: node:crypto — для sha256, path — для resolve в relativeProjectPath. Остальные функции (toPosixPath, isProbablyExcluded, encodeResourceId, decodeResourceId) не зависят ни от каких модулей. Ни одна функция не обращается к файловой системе, не требует внешних npm-пакетов или конфигурации проекта. При этом она сама не обрабатывает ошибки — вызывающий код должен полагаться на подсистему «Единый формат ошибок» для согласованного представления сбоев.

## Кто и как использует

Вызов relativeProjectPath запускает цепочку: он принимает абсолютный путь и корень проекта, вызывает resolve для вычисления относительного пути, затем toPosixPath для замены обратных слешей на прямые. Остальные функции (sha256, isProbablyExcluded, encodeResourceId, decodeResourceId) работают изолированно, не вызывая друг друга. Типичный поток от вызывающего кода: строка хешируется sha256; путь нормализуется через toPosixPath, затем relativeProjectPath вычисляет относительный путь от корня, isProbablyExcluded решает, включать ли результат в индексацию; для MCP-сервиса encodeResourceId кодирует идентификатор, decodeResourceId восстанавливает на принимающей стороне.

## Чего не делает

sha256 не нормализует вход — разные регистры или пробелы дают разные дайджесты. toPosixPath не меняет регистр, не разрешает симлинки и не проверяет существование пути. relativeProjectPath не проверяет, что путь находится внутри корня — результат может содержать '..'. isProbablyExcluded не обрабатывает glob или регулярные выражения. encodeResourceId и decodeResourceId не проверяют валидность идентификатора, не добавляют URI-префикс или схему — это задача вызывающего кода.
