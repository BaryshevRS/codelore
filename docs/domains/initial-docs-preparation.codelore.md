## Зачем это нужно

По списку сущностей кода и области фильтрации определяет, для каких сущностей нужны новые страницы документации. Для новых страниц создаёт скелетные DocState с пустыми телами блоков и отпечатками, пропуская уже задокументированные сущности. Это позволяет следующему этапу конвейера наполнять блоки содержимым, не отвлекаясь на построение структуры.

## Что делает

Нормализует входящий скоуп фильтрации (normalizePrepareScope), планирует разметку файлов (planFileLayout), проверяет вхождение сущностей в область (isEntityInPrepareScope) и необходимость создания страницы (shouldCreatePage). Для новых страниц создаёт скелетные секции (docStateSectionForPlannedEntity) с упорядоченными блоками, якорями и отпечатками. Для уже задокументированных сущностей фиксирует пропуск (skippedPreparedDocSection). Собирает итоговый результат (preparedDocsResult) со сводкой и указанием следующего шага.

## От чего зависит

Для нормализации путей подсистема использует toPosixPath из «Общие низкоуровневые утилиты», а для дедупликации массивов — uniqueSorted из «Общие вспомогательные функции сервиса». Вычисление отпечатков блоков (computeBlockFingerprint) — внешняя функция, которую подсистема вызывает, но не предоставляет сама. Подсистема не генерирует содержимое блоков — все тела остаются пустыми строками, не сохраняет DocState на диск и не проверяет целостность идентификаторов блоков, доверяя источнику allowedBlockIds.

## Кто и как использует

Входящий скоуп фильтрации нормализуется через normalizePrepareScope: пути приводятся к POSIX-формату, удаляются дубликаты. Затем для каждого файла planFileLayout сортирует сущности по startOffset и назначает заголовки первого уровня. Для каждой сущности isEntityInPrepareScope проверяет вхождение в область, shouldCreatePage — необходимость создания страницы. Если сущность уже задокументирована, skippedPreparedDocSection фиксирует пропуск. Для новых страниц docStateSectionForPlannedEntity получает разрешённые блоки (allowedBlockIds), упорядочивает их (orderBlocks), генерирует якорь из заголовка (anchorForHeading), для каждого блока создаёт запись с пустым телом и отпечатком (computeBlockFingerprint). В конце preparedDocsResult собирает все созданные, запланированные и пропущенные секции, формирует сводку и определяет следующий шаг (prepareInitialDocsNextStep).

## Чего не делает

Не создаёт страницы для сущностей с ролью, отличной от short_page или full_page — такие сущности исключаются из плана. Не обрабатывает вложенность страниц: каждая сущность либо получает отдельную страницу, либо пропускается. Если сущность уже задокументирована, её секция только регистрируется как пропущенная, но не обновляется. Не проверяет целостность идентификаторов блоков, доверяя источнику allowedBlockIds. Не генерирует содержимое блоков — все тела остаются пустыми строками. Не сохраняет DocState на диск, только формирует структуры в памяти.
