# Подготовка первичной документации

## Состав

- [file-layout](../../src/service/file-layout.codelore.md) — Преобразует список сущностей кода в структурированный план секций документации для одного файла.
- [prepare-docs](../../src/service/prepare-docs.codelore.md) — Создаёт пустой `DocState` для нового документа, заданного путём.

**Зависит от:** [Отпечатки блоков документации](block-fingerprinting.codelore.md#отпечатки-блоков-документации) · [Общие низкоуровневые утилиты](common-utils.codelore.md#общие-низкоуровневые-утилиты) · [Общие вспомогательные функции сервиса](service-helpers.codelore.md#общие-вспомогательные-функции-сервиса)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore)

## Зачем это нужно

По списку сущностей кода и области фильтрации определяет, для каких сущностей нужны новые страницы документации, и создаёт для них скелетные DocState с пустыми телами блоков и отпечатками, пропуская уже задокументированные сущности. Это позволяет следующему этапу конвейера наполнять блоки содержимым, не отвлекаясь на построение структуры.

## От чего зависит

Опирается на подсистему «Отпечатки блоков документации» для вычисления computeBlockFingerprint при создании скелета секции. Использует toPosixPath из «Общие низкоуровневые утилиты» для нормализации путей файлов и uniqueSorted из «Общие вспомогательные функции сервиса» для дедупликации и сортировки массивов зависимостей, потребителей и путей. Сама не генерирует содержимое блоков, а создаёт скелетные DocState с пустыми телами блоков и отпечатками, пропуская уже задокументированные сущности; не записывает файлы на диск и не проверяет корректность идентификаторов блоков — эти задачи выполняются следующими этапами.

## Кто и как использует

Входящий скоуп фильтрации нормализуется (normalizePrepareScope): пути приводятся к POSIX-формату, удаляются дубликаты. Затем для каждого файла в области готовится план секций (planFileLayout): сущности сортируются по startOffset, им назначаются заголовки первого уровня. Для каждой сущности, проходящей фильтр (isEntityInPrepareScope), проверяется, должна ли создаваться страница (shouldCreatePage). Если сущность уже задокументирована, она фиксируется как пропущенная (skippedPreparedDocSection). Для новых страниц вызывается docStateSectionForPlannedEntity: она получает разрешённые блоки (allowedBlockIds), упорядочивает их (orderBlocks), генерирует якорь из заголовка (anchorForHeading), и для каждого блока создаёт запись с пустым телом и отпечатком (computeBlockFingerprint). В конце preparedDocsResult собирает все созданные, запланированные и пропущенные секции, формирует сводку и определяет следующий шаг (prepareInitialDocsNextStep). В результате формируются скелетные DocState с пустыми телами блоков и отпечатками, пропуская уже задокументированные сущности.

## Чего не делает

Не генерирует содержимое блоков — все тела остаются пустыми строками. Не сохраняет DocState на диск, только формирует структуры в памяти. Не проверяет целостность идентификаторов блоков, доверяя источнику (allowedBlockIds). Не создаёт страницы для сущностей с ролью, отличной от short_page или full_page; такие сущности исключаются из плана. Не обрабатывает вложенность страниц — каждая сущность либо получает отдельную страницу, либо пропускается. Если сущность уже задокументирована, её секция не обновляется, а только регистрируется как пропущенная. Ограничивается созданием скелетных DocState с пустыми телами блоков и отпечатками, пропуская уже задокументированные сущности.
