## Зачем это нужно

Подсистема готовит первичную документацию: по списку сущностей кода и области фильтрации она строит скелетные состояния DocState для новых страниц, оставляя тела блоков пустыми, и пропускает уже задокументированные сущности. Для этого она использует планирование структуры файлов, преобразование запланированных сущностей в секции через `docStateSectionForPlannedEntity`, а также сборку скелетов доменных документов через [`buildDomainSkeletons`](../../src/service/domain-docs.codelore.md#builddomainskeletons). Результат передаётся следующему этапу конвейера для наполнения содержимым.

## Что делает

Подсистема нормализует входящий скоуп: приводит пути к POSIX-формату через `normalizePreparePath`, удаляет дубликаты и гарантирует, что `dryRun` — булево значение. Для каждого файла `planFileLayout` сортирует сущности по `startOffset` и назначает заголовки первого уровня. Дальше для каждой сущности `isEntityInPrepareScope` проверяет вхождение в область, а `shouldCreatePage` — роль: страницу получают только сущности с ролью `short_page` или `full_page` (или без роли). Для новых страниц `docStateSectionForPlannedEntity` строит скелетную секцию: упорядочивает разрешённые блоки по каноническому списку, генерирует якорь из заголовка, вычисляет отпечаток каждого блока и собирает `depends`/`usedBy` из прямых зависимостей сущности; `withPreservedBlockBodies` переносит непустые тела блоков из предыдущего состояния. Уже задокументированные сущности подсистема регистрирует как пропущенные через `skippedPreparedDocSection`. В конце `preparedDocsResult` собирает результат: сводку, пропущенные блоки по сущностям и следующее действие — остановиться, выполнить без `--dry-run` или заполнить созданные секции.

## От чего зависит

Для нормализации путей подсистема вызывает `toPosixPath` из «Общих низкоуровневых утилит», а для дедупликации массивов — `uniqueSorted` из «Общих вспомогательных функций сервиса». Отпечатки блоков она не вычисляет сама: `computeBlockFingerprint` — внешняя функция, которую подсистема только вызывает. Подсистема сознательно не генерирует содержимое блоков — все тела остаются пустыми строками, — не сохраняет DocState на диск и не проверяет целостность идентификаторов блоков, доверяя источнику `allowedBlockIds`.

## Кто и как использует

Запрос приходит со скоупом фильтрации и списком сущностей. `normalizePrepareScope` приводит скоуп к нормальному виду: пути через `normalizePreparePath` становятся POSIX-совместимыми, дубликаты удаляются, `dryRun` по умолчанию получает `false`. Затем `planFileLayout` для каждого файла сортирует сущности по `startOffset` и назначает заголовки первого уровня. Для каждой сущности `isEntityInPrepareScope` проверяет вхождение в область, а `shouldCreatePage` — роль. Если сущность уже задокументирована, `skippedPreparedDocSection` формирует запись о пропуске с причиной `already_documented`. Для новых страниц `docStateSectionForPlannedEntity` получает разрешённые блоки через `allowedBlockIds`, упорядочивает их через `orderBlocks`, генерирует якорь через `anchorForHeading` и для каждого блока создаёт запись с пустым телом и отпечатком от `computeBlockFingerprint`; `withPreservedBlockBodies` переносит непустые тела из предыдущего состояния. Кроме того, [`buildDomainSkeletons`](../../src/service/domain-docs.codelore.md#builddomainskeletons) строит скелеты доменных документов с упорядоченным списком идентификаторов секций. В конце `preparedDocsResult` собирает созданные, запланированные и пропущенные секции, `prepareInitialDocsSummary` формирует сводку, а `prepareInitialDocsNextStep` определяет следующее действие.

## Чего не делает

Подсистема не создаёт страницы для сущностей с ролью, отличной от `short_page` или `full_page`, — такие сущности исключаются из плана. Вложенность страниц она не обрабатывает: каждая сущность либо получает отдельную страницу, либо пропускается. Если сущность уже задокументирована, её секция не обновляется — подсистема только регистрирует пропуск. Она не проверяет, что идентификаторы из `allowedBlockIds` относятся к реальным блокам, и не генерирует содержимое: все тела блоков остаются пустыми строками. Результат существует только в памяти — на диск DocState не сохраняется.
