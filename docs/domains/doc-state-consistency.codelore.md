# Согласование и валидация состояния документации

## Состав

- [doc-reconcile](../../src/service/doc-reconcile.codelore.md) — Синхронизирует `DocState` с текущим набором сущностей кода: удаляет секции, чья сущность исчезла, и обрезает блоки, не разрешённые для сущности.
- [doc-validation](../../src/service/doc-validation.codelore.md) — Сигнализирует о секциях, которые ссылаются на несуществующие сущности в поле `owns`.

**Зависит от:** [Отпечатки блоков документации](block-fingerprinting.codelore.md#отпечатки-блоков-документации) · [Общие вспомогательные функции сервиса](service-helpers.codelore.md#общие-вспомогательные-функции-сервиса) · [Обнаружение устаревших блоков документации](stale-blocks-detection.codelore.md#обнаружение-устаревших-блоков-документации)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore)

## Зачем это нужно

Подсистема согласует DocState с текущим кодом и выявляет проблемы документации: удаляет секции, чьи сущности исчезли, и блоки, не разрешённые для типа сущности, а также находит битые ссылки на сущности и секции, устаревшие блоки по расхождению отпечатков и пустые или заглушечные тела. Вышестоящие слои сервиса используют её, чтобы вовремя заметить и исправить проблемы цельности документации.

## Что делает

Подсистема владеет согласованием и валидацией. reconcileDocStateWithCode мутирует DocState: удаляет секции без владельцев и лишние блоки, не входящие в allowedBlocks. Валидация не трогает состояние — она возвращает массив проблем: validateOwnedEntities и validateDependencies находят битые ссылки, detectStaleBlocks сравнивает отпечатки блоков через подсистему отпечатков, validateBlockQuality отсеивает пустые и неотрисованные тела. Каждая проблема — объект DocValidationIssue с уровнем error или warning.

## От чего зависит

Для детекции устаревших блоков подсистема вычисляет текущие отпечатки через подсистему «Отпечатки блоков документации» и сравнивает с сохранёнными; без неё проверка невозможна. Для дедупликации, группировки и проверки идентификаторов использует общие утилиты. Список разрешённых блоков получает из метаданных сущностей, а не определяет самостоятельно. Хранением отпечатков не занимается.

## Кто и как использует

Сначала вызывается reconcileDocStateWithCode, получая DocState и текущие сущности кода. Функция мутирует состояние: удаляет секции, чьи владельцы отсутствуют, и для каждой оставшейся секции вырезает блоки, не входящие в allowedBlocks. Затем запускаются проверки: validateOwnedEntities и validateDependencies ищут битые ссылки, detectStaleBlocks для каждого блока с известным идентификатором вычисляет отпечаток через подсистему и сравнивает с сохранённым, validateBlockQuality отсеивает неотрисованные и пустые тела. Все проверки возвращают массивы проблем, которые агрегируются вызывающим кодом. Согласование всегда предшествует валидации, чтобы исключить ложные срабатывания на уже удалённых сущностях.

## Чего не делает

Подсистема только удаляет исчезнувшие секции и недопустимые блоки, а добавление секций для появившихся сущностей — задача другого модуля. Валидация не проверяет транзитивные зависимости и не анализирует допустимость типа владельца. Блок считается устаревшим только при успешном вычислении отпечатка и только если его идентификатор распознан; нераспознанные блоки игнорируются. Качество проверяется лишь по отсутствию тела, а не по смысловой полноте. Подсистема только сигнализирует о проблемах, не исправляет их.
