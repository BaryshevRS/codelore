## Зачем это нужно

Подсистема парсит JSON из ответа LLM и, если разбор не удался, повторяет запрос с обратной связью до успеха или исчерпания попыток. Модель может вернуть невалидный JSON с Markdown-фенсами, экранированными обратными кавычками или другими артефактами — подсистема исправляет известные искажения и парсит ответ. В итоге наружу выходит либо объект, либо ошибка (например, CodeloreError с кодом INVALID_LLM_RESPONSE при неудаче парсинга после всех попыток, или ошибка провайдера), освобождая остальную систему от реализации логики повторов и обработки JSON-артефактов.

## Что делает

Подсистема принимает запрос к LLM, функцию вызова complete и лимит повторов. Она снимает внешний Markdown-фенс, парсит JSON, при неудаче применяет repairKnownLlmEscapes — исправление трёх известных артефактов — и пробует распарсить снова. Если обе попытки сорвались, выбрасывается CodeloreError с кодом INVALID_LLM_RESPONSE. При ошибке парсинга, не являющейся INVALID_LLM_RESPONSE, или при превышении лимита ретраев, выполняется запись отладки, затем ошибка пробрасывается. readOptionalString позволяет безопасно забрать опциональные строки из полученного объекта: нет поля — возвращает undefined, поле есть, но не строка — выбрасывает INVALID_LLM_RESPONSE.

## От чего зависит

Подсистема полагается на единый формат ошибок — CodeloreError с кодом INVALID_LLM_RESPONSE — как на общий сигнал о неудачном разборе, понятный всем верхним слоям. Она также использует функцию complete, предоставляемую провайдером LLM, для выполнения запросов. Подсистема не валидирует внутреннюю структуру разобранного JSON дальше проверки, что результат — объект, и не обрабатывает ошибки провайдера, не связанные с разбором, — они пробрасываются наверх.

## Кто и как использует

Запрос к LLM передаётся в completeAndParse, который вызывает complete и передаёт ответ в parseJsonObject. Тот последовательно снимает внешний Markdown-фенс, парсит JSON, при провале — чинит ответ через repairKnownLlmEscapes и парсит снова. Если parseJsonObject выбросил INVALID_LLM_RESPONSE, completeAndParse проверяет лимит: если попытки ещё есть, создаёт новую копию запроса с дополненной историей — assistant-сообщение содержит провальный ответ, user-сообщение описывает ошибку — и повторяет вызов complete. После успешного разбора readOptionalString извлекает опциональные строковые поля: отсутствующее поле даёт undefined, значение не-строка вызывает выброс INVALID_LLM_RESPONSE.

## Чего не делает

Повторы выполняются только для ошибок разбора с кодом INVALID_LLM_RESPONSE; ошибки провайдера, не являющиеся этим кодом, не вызывают ретраев и пробрасываются сразу. repairKnownLlmEscapes исправляет только три известных LLM-артефакта: экранированные обратные кавычки, \$ и \\. readOptionalString извлекает только строковые поля: отсутствующее поле даёт undefined, значение не-строка вызывает выброс INVALID_LLM_RESPONSE. Подсистема не валидирует содержимое строк и не проверяет структуру объекта дальше того, что это объект.
