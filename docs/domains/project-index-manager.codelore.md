# Управление индексом проекта

## Состав

- [index-manager](../../src/service/index-manager.codelore.md) — Управляет сборкой, кэшированием и проверкой свежести `ProjectIndex`.

**Зависит от:** [Индексация кода и документации](code-doc-indexing.codelore.md#индексация-кода-и-документации) · [Хранилище состояния документации](doc-state-storage.codelore.md#хранилище-состояния-документации) · [Хранилище индексов и анализа изменений](json-storage.codelore.md#хранилище-индексов-и-анализа-изменений)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore)

## Зачем это нужно

Предоставляет единую точку для получения актуального ProjectIndex, объединяющего код и документацию. IndexManager автоматически проверяет свежесть кэша и перестраивает индекс при необходимости, избавляя остальную систему от повторной сборки и проверки.

## Что делает

IndexManager запускает параллельную сборку код- и док-индексов через buildCodeIndex и buildDocIndex. Проверяет свежесть сохранённого индекса по времени модификации файлов относительно generatedAt. Хранит кэш в приватном поле cache и сбрасывает его при перестроении через колбэк onIndexChanged. Для точечных обновлений документации вызывает patchDocIndexPaths.

## От чего зависит

Для построения индексов использует buildCodeIndex и buildDocIndex из подсистемы индексации кода и документации. Сохранение и загрузку кэша делегирует хранилищу индексов и анализа изменений. Точечное обновление документации выполняет через patchDocIndexPaths, предоставляемый хранилищем состояния документации. Сам IndexManager не строит индексы, не пишет на диск и не управляет состоянием документации.

## Кто и как использует

При запросе индекса IndexManager проверяет кэш: если он пуст или устарел (persistedIndexIsFresh возвращает false), запускает параллельную сборку buildCodeIndex и buildDocIndex, формирует ProjectIndex, сохраняет его через хранилище индексов, обновляет cache и вызывает onIndexChanged. Для точечного обновления документации вызывается patchDocIndexPaths, который изменяет только указанные пути в док-индексе, не трогая код-индекс.

## Чего не делает

IndexManager не выполняет построение индексов самостоятельно — только координирует вызовы внешних билдеров. Не обрабатывает ошибки индексации, пробрасывает их вызывающему коду. Не гарантирует атомарность обновления кэша при конкурентных вызовах. Не управляет сохранением на диск напрямую — делегирует хранилищу.
