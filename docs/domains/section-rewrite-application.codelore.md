# Применение перезаписей секций

## Состав

- [section-rewrite](../../src/service/section-rewrite.codelore.md) — Группирует запросы на перезапись секций по пути документа для пакетной обработки.

**Зависит от:** [Отпечатки блоков документации](block-fingerprinting.codelore.md#отпечатки-блоков-документации) · [Хранилище состояния документации](doc-state-storage.codelore.md#хранилище-состояния-документации) · [Единый формат ошибок](error-handling.codelore.md#единый-формат-ошибок) · [Общие вспомогательные функции сервиса](service-helpers.codelore.md#общие-вспомогательные-функции-сервиса)
**Используется в:** [Фасад сервиса Codelore](codelore-service-facade.codelore.md#фасад-сервиса-codelore)

## Зачем это нужно

Подсистема принимает запросы на перезапись секций сгенерированными блоками, группирует их по документу и вливает каждый блок в состояние секции: вычисляет отпечаток, обновляет тело, оценки и сбрасывает флаги устаревания, после чего обновляет метаданные секции и сохраняет документ. Это позволяет безопасно зафиксировать результат работы генератора в хранилище документации с актуальным статусом свежести.

## Что делает

Отвечает за полный цикл обновления документа: нормализует входные перезаписи, оставляя только блоки с идентификаторами из фиксированного набора BLOCK_IDS; группирует перезаписи по документу; для каждого документа загружает состояние, перебирает перезаписи и для каждой: находит секцию, вызывает слияние (перезаписывает отпечатки, тело, оценки, сбрасывает дату устаревания, дополняет blockOrder и allowedBlocks, обновляет поля depends/usedBy из сущности владельца, если есть), пересчитывает статус секции. После всех перезаписей обновляет метку времени и сохраняет документ через хранилище. По запросу может собрать отфильтрованные блоки для ответа.

## От чего зависит

Опирается на подсистемы: «Хранилище состояния документации» для загрузки и атомарного сохранения состояния; «Отпечатки блоков документации» для вычисления хеша блока; «Общие вспомогательные функции сервиса» для сортировки зависимостей (uniqueSorted) и списка допустимых идентификаторов блоков (BLOCK_IDS); «Единый формат ошибок» для выброса CodeloreError с кодами UNKNOWN_SECTION, UNKNOWN_DOC, MISSING_GENERATED_BLOCKS. Сама подсистема не валидирует содержимое блоков (текст, оценки) и не управляет конкурентным доступом к документу — эти заботы делегированы хранилищу или вызывающему коду.

## Кто и как использует

1. Нормализация: normalizeGeneratedRewrite отфильтровывает блоки из generatedBlocks, оставляя только те, чьи ключи есть в BLOCK_IDS; проверяет, что сгенерированных блоков не ноль. 2. Группировка: groupRewritesByDoc строит Map docPath → массив перезаписей, попутно проверяя существование секции. 3. Применение к документу: applyRewritesToDoc загружает состояние, для каждой перезаписи вызывает mergeGeneratedBlocksIntoSection, потом обновляет generatedAt и сохраняет. 4. Слияние в секцию: mergeGeneratedBlocksIntoSection для каждого блока вычисляет отпечаток, записывает текст/оценки/язык, сбрасывает staleSince, при необходимости добавляет идентификатор в blockOrder и allowedBlocks; если у секции есть владелец, синхронизирует depends/usedBy; вызывает updateSectionStatusForBlocks. 5. Статус: updateSectionStatusForBlocks пропускает секции с review_needed, иначе считает allBlocksStale — если все блоки устарели, ставит stale, иначе normal. 6. Сбор отфильтрованных: если showFiltered, collectFilteredBlocksForRewrites вызывает collectFilteredBlocksForResponse, которая выбирает блоки с оценками и rendered=false, вычисляет finalScore и применяет порог, опционально включает текст.

## Чего не делает

Не проверяет качество или валидность сгенерированного текста блоков. Игнорирует любые идентификаторы блоков, не перечисленные в BLOCK_IDS. Не поддерживает конкурентные изменения одного документа: повторные или параллельные сохранения могут привести к конфликтам, если хранилище не обеспечивает блокировку. Прерывает обработку при первой ошибке (неизвестная секция или отсутствующий документ) и не откатывает уже применённые к другим документам изменения. Секции со статусом review_needed не получают автоматическое обновление статуса, даже если после перезаписи их блоки стали свежими.
