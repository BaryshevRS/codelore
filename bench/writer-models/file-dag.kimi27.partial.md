# file-dag.ts

## Зачем это нужно

Определяет порядок обработки файлов при генерации документации: строит ориентированный граф файловых зависимостей по индексу кода и раскладывает произвольный набор файлов в отсортированные волны, объединяя циклически связанные файлы в одну волну.

## Что делает

- Строит файловый DAG из CodeIndex: для каждого файла из `code.fileToEntities` создаёт вершину, а для каждой сущности добавляет файлы её прямых зависимостей, отбрасывая петли и зависимости от файлов вне индекса.
- Вычисляет волны генерации для переданного подмножества файлов: фильтрует файлы по графу, выделяет компоненты сильной связности, назначает каждой компоненте минимальный уровень, при котором все её зависимости уже обработаны, и возвращает детерминированно отсортированный массив волн.
- Экспортирует тип `FileDag` как `Map<string, Set<string>>`, где ключ — файл, а значение — множество файлов, от которых он напрямую зависит.

## На что можно положиться

- Граф строится по ключам `code.fileToEntities`, но волны формируются только из файлов, переданных в `files` и присутствующих в графе; файлы вне `code.fileToEntities` игнорируются.
- Результат `generationWaves` детерминирован: волны упорядочены по возрастанию уровня, а группы внутри одной волны — по первому файлу.

## Чего не делает

Граф файлов строится только из ключей `Object.keys(code.fileToEntities)` — файлы, отсутствующие в этом объекте, не попадают ни в граф, ни в волны. Зависимости, чья сущность не найдена в `code.entities`, ведёт на тот же файл или на файл вне графа, отбрасываются условием `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)` в `buildFileDag`. Волны вычисляются только для файлов, прошедших фильтр `dag.has(file)` в `generationWaves`; файлы, не попавшие в граф, молча игнорируются.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Собирает `Map` файловых зависимостей из `CodeIndex`, превращая прямые зависимости сущностей в зависимости между файлами и отбрасывая самозависимости и ссылки на файлы вне индекса.

## Что делает

- Создаёт вершину с пустым множеством зависимостей для каждого файла из `code.fileToEntities`.
- Для каждой сущности из `code.entities` добавляет в множество её файла путь файла каждой прямой зависимости, но только если зависимая сущность существует, её файл отличается от файла владельца и сам файл зависимости уже есть в графе.
- Возвращает `FileDag`, где ключ — файл, а значение — множество файлов, от которых он напрямую зависит.

## На что можно положиться

- Каждое ребро соответствует прямой зависимости сущности, но добавляется только при одновременном выполнении трёх условий: зависимая сущность существует в `code.entities`, её путь отличается от пути владельца, и файл зависимости присутствует в графе; иначе зависимость игнорируется.

## Кто и как использует

`generationWaves` (src/graph/file-dag.ts) вызывает `buildFileDag`, чтобы построить DAG, который затем участвует в выделении компонент сильной связности и вычислении волн генерации. `collectDependencyDocs` (src/llm/file-pipeline.ts) вызывает `buildFileDag`, чтобы определить файлы-зависимости за пределами текущей группы, и затем формирует `DependencyDoc` с учётом лимита `DEP_DOCS_TOTAL_CAP`. `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) вызывают `buildFileDag`, чтобы построить граф для визуализации пирамиды зависимостей.

## Чего не делает

Набор вершин графа ограничен итерацией `Object.keys(code.fileToEntities)` — файлы вне объекта не попадут в результат. Зависимости отбрасываются, если сущность не найдена в `code.entities`, если её путь совпадает с путём владельца (`depEntity.path !== entity.path`), или если файл зависимости отсутствует в графе (`dag.has(depEntity.path)`); все три проверки объединены в условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

## Как менять и что проверять

1. Множество вершин графа формируется итерацией `Object.keys(code.fileToEntities)` — каждый ключ становится вершиной с пустым множеством зависимостей.
2. Самозависимости исключаются проверкой `depEntity.path !== entity.path` внутри условия `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Вычисляет минимальные волны генерации для заданного набора файлов: разбивает их на компоненты сильной связности и назначает каждой компоненте уровень, при котором все её файловые зависимости уже обработаны, объединяя циклы в одну волну.

## Что делает

- Строит файловый DAG через `buildFileDag` и ограничивает область переданными файлами, присутствующими в графе.
- Выделяет компоненты сильной связности среди отфильтрованных файлов с помощью `stronglyConnectedComponents`.
- Присваивает каждой компоненте уровень как максимум уровней зависимостей плюс один, кэшируя уже вычисленные уровни в массиве `levels`.
- Раскладывает компоненты по волнам, сортирует группы внутри волны по первому файлу и возвращает массив волн, упорядоченных по возрастанию уровня.

## На что можно положиться

- Входной список файлов фильтруется по наличию в графе: `files.filter((file) => dag.has(file))`.
- Все файлы одной компоненты сильной связности попадают в одну и ту же волну.
- Уровень компоненты равен максимуму уровней зависимостей плюс один, поэтому зависимости всегда обрабатываются раньше зависимых компонент.
- Группы внутри волны сортируются по первому файлу: `left[0].localeCompare(right[0])`.

## Кто и как использует

Вызывается из `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) для получения волн генерации. Оба вызова передают индекс кода и список файлов, полученный из проекта. Результат (волны) затем визуализируется в виде пирамиды зависимостей: текстовой в `renderGraphTree` или в виде графа Cytoscape.js в `renderGraphHtml`.

## Чего не делает

Область действия ограничена файлами, присутствующими в DAG: фильтр `files.filter((file) => dag.has(file))` отбрасывает файлы без записей в `code.fileToEntities`. Сортировка волн использует первый файл каждой группы: `left[0].localeCompare(right[0])`, что не учитывает остальные файлы группы.

## Как менять и что проверять

1. Входной список файлов ограничивается файлами, присутствующими в графе: фильтр `files.filter((file) => dag.has(file))`.
2. Группы внутри волны сортируются по первому файлу: `left[0].localeCompare(right[0])`.
