# file-dag.ts

## Зачем это нужно

Определяет порядок, в котором конвейер документирования обходит файлы проекта: строит граф прямых межфайловых зависимостей и делит любой переданный набор файлов на волны, объединяя взаимно зависящие (циклические) файлы в одну волну, чтобы генерация докстрок шла от листовых зависимостей к зависящим от них файлам.

## Что делает

- `buildFileDag` строит граф файловых зависимостей: вершина на файл из `code.fileToEntities`, ребро на каждую сущность, чья прямая зависимость лежит в другом файле индекса.
- `generationWaves` использует этот граф, чтобы выделить компоненты сильной связности (внутренний хелпер `stronglyConnectedComponents`, алгоритм Тарьяна на явном стеке вместо рекурсии) и схлопнуть циклы в одну группу.
- `generationWaves` присваивает каждой группе уровень (волну) как максимум уровней групп-зависимостей плюс один, формируя минимально возможное число волн.
- Обе функции разделяют одну и ту же область видимости файлов: файлы, отсутствующие в `code.fileToEntities`, не участвуют ни в графе, ни в волнах.

## На что можно положиться

- Граф и волны согласованы по составу файлов: волны строятся только из файлов, которые есть в графе `buildFileDag`, то есть присутствуют в `code.fileToEntities`.
- Вывод обоих этапов детерминирован: одинаковый вход всегда даёт одинаковый граф и одинаковый порядок волн — это общий контракт, на который опираются потребители (рендер графа, сбор зависимостей).
- Циклически связанные файлы всегда оказываются в одной и той же волне, независимо от того, в каком порядке они были переданы в `generationWaves`.

## Чего не делает

Граф файлов строится только из ключей `Object.keys(code.fileToEntities)` — файлы, отсутствующие в этом объекте, не попадают ни в граф, ни в волны. Зависимости, чья сущность не найдена в `code.entities`, ведёт на тот же файл или на файл вне графа, отбрасываются условием `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)` в `buildFileDag`. Волны вычисляются только для файлов, прошедших фильтр `dag.has(file)` в `generationWaves`; файлы, не попавшие в граф, молча игнорируются.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Строит граф прямых зависимостей между файлами проекта, чтобы `generationWaves` мог упорядочить обработку файлов и не спутать зависимость файла с зависимостью на самого себя или на файл вне индекса.

## Что делает

- Создаёт вершину с пустым множеством зависимостей для каждого файла из `code.fileToEntities`.
- Проходит по всем сущностям `code.entities` и для каждой зависимости из `entity.directDeps` находит файл этой зависимости.
- Добавляет найденный файл в множество зависимостей файла-владельца только если зависимая сущность найдена, её файл отличается от файла владельца и этот файл присутствует в графе: `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

## На что можно положиться

- Возвращаемая карта содержит ровно те файлы, что есть в `code.fileToEntities` — не больше и не меньше.
- Файл никогда не оказывается зависимым от самого себя: гарантируется проверкой `depEntity.path !== entity.path`.
- Ссылки на файлы вне графа (отсутствующие в `code.fileToEntities`) отбрасываются молча — потребитель не получит рёбер, ведущих в никуда.

## Кто и как использует

`generationWaves` (src/graph/file-dag.ts) вызывает `buildFileDag`, чтобы построить DAG, который затем участвует в выделении компонент сильной связности и вычислении волн генерации. `collectDependencyDocs` (src/llm/file-pipeline.ts) вызывает `buildFileDag`, чтобы определить файлы-зависимости за пределами текущей группы файлов, и на основе этого формирует список `DependencyDoc`. `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) вызывают `buildFileDag`, чтобы построить граф для визуализации пирамиды зависимостей — соответственно в виде интерактивного графа Cytoscape.js и в виде текстового дерева.

## Чего не делает

Набор вершин графа ограничен итерацией `Object.keys(code.fileToEntities)` — файлы вне объекта не попадут в результат. Зависимости отбрасываются, если сущность не найдена в `code.entities`, если её путь совпадает с путём владельца (`depEntity.path !== entity.path`), или если файл зависимости отсутствует в графе (`dag.has(depEntity.path)`); все три проверки объединены в условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Вычисляет минимальный набор волн генерации для переданных файлов так, чтобы файл-зависимость всегда обрабатывался раньше зависящего от него файла, а файлы, образующие цикл зависимостей, попадали в одну и ту же волну.

## Что делает

- Строит граф через `buildFileDag` и сужает область до файлов, присутствующих в графе: `files.filter((file) => dag.has(file))`.
- Выделяет компоненты сильной связности среди файлов области с помощью внутреннего хелпера `stronglyConnectedComponents`, схлопывая циклы в единые группы.
- Рекурсивно вычисляет уровень каждой группы (`levelOf`) как максимум уровней групп, от которых она зависит, плюс один; результат мемоизируется в массиве `levels`, так что каждая группа пересчитывается один раз.
- Собирает волны: каждая волна — массив групп файлов, отсортированных внутри волны по первому файлу группы, а сами волны идут по возрастанию уровня.

## На что можно положиться

- Если после фильтрации `dag.has(file)` область файлов пуста, компоненты не выделяются и функция возвращает пустой массив волн.
- Если файл A зависит от файла B не через цикл, волна A строго больше волны B: это гарантирует `level = Math.max(level, levelOf(depGroup) + 1)`.
- Все файлы одной компоненты сильной связности всегда попадают в одну и ту же волну.
- Порядок вывода детерминирован: группы внутри волны сортируются по первому файлу (`left[0].localeCompare(right[0])`), а волны идут по возрастанию уровня.

## От чего зависит

Зависит от `buildFileDag` (src/graph/file-dag.ts) для построения графа файловых зависимостей и от `stronglyConnectedComponents` (src/graph/file-dag.ts) для выделения компонент сильной связности, на основе которых вычисляются уровни (волны).

## Кто и как использует

Вызывается из `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts), которые передают индекс кода и список файлов проекта и используют возвращённые волны для построения пирамиды зависимостей: `renderGraphHtml` раскладывает узлы по волнам для позиционирования графа Cytoscape.js, а `renderGraphTree` печатает волны построчно как текстовое дерево.

## Чего не делает

Область действия ограничена файлами, присутствующими в DAG: фильтр `files.filter((file) => dag.has(file))` отбрасывает файлы без записей в `code.fileToEntities`. Сортировка волн использует только первый файл каждой группы: `left[0].localeCompare(right[0])`, то есть порядок волн не зависит от остальных файлов внутри группы.
