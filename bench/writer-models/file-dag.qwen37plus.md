# file-dag.ts

## Зачем это нужно

Вычисляет порядок обработки файлов для генерации документации, представляя зависимости между файлами в виде ориентированного графа и разбивая их на детерминированные волны с учётом циклических связей.

## Что делает

- Строит ориентированный граф файловых зависимостей из индекса кода, где вершинами выступают файлы, а рёбрами — прямые зависимости между сущностями этих файлов.
- Разбивает произвольный набор файлов на волны генерации, группируя циклически связанные файлы в одну волну и упорядочивая волны так, чтобы зависимости всегда обрабатывались раньше зависимых от них файлов.

## На что можно положиться

- Граф не содержит петель: файл никогда не зависит сам от себя.
- Волны генерации детерминированы: группы файлов внутри каждой волны отсортированы по первому файлу, а сами волны упорядочены по возрастанию уровня зависимости.
- Файлы, отсутствующие в индексе кода, полностью игнорируются и не попадают ни в граф, ни в результирующие волны.

## Чего не делает

- Рёбра графа отражают только прямые зависимости сущностей, транзитивные связи не вычисляются, что жёстко задано циклом `for (const depId of entity.directDeps)`.
- Сортировка групп внутри волны опирается исключительно на первый файл группы, что принудительно задаётся выражением `left[0].localeCompare(right[0])` и игнорирует порядок остальных файлов в компоненте.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Формирует ориентированный граф прямых файловых зависимостей на основе индекса кода, отбрасывая самозависимости и ссылки на файлы вне индекса.

## Что делает

- Инициализирует вершины графа для каждого файла, присутствующего в `code.fileToEntities`, создавая для них пустые множества зависимостей.
- Обходит все сущности индекса и добавляет файлы их прямых зависимостей в множество файла-владельца, применяя строгую фильтрацию.
- Возвращает структуру `Map<string, Set<string>>`, отображающую каждый файл на множество файлов, от которых он напрямую зависит.

## На что можно положиться

- Множество вершин графа в точности совпадает с ключами `code.fileToEntities`.
- Условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)` гарантирует, что в граф не попадают самозависимости, несуществующие сущности и файлы вне индекса.

## Кто и как использует

1. `generationWaves` (src/graph/file-dag.ts) вызывает функцию для построения графа, который затем используется для выделения компонент сильной связности и распределения файлов по волнам.
2. `collectDependencyDocs` (src/llm/file-pipeline.ts) строит граф, чтобы найти файлы-зависимости за пределами текущей обрабатываемой группы, и формирует из них `DependencyDoc` с учётом лимита `DEP_DOCS_TOTAL_CAP`.
3. `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) используют граф для визуализации пирамиды зависимостей: первая рендерит интерактивный граф Cytoscape.js, вторая выводит текстовое представление волн.

## Чего не делает

- Множество вершин графа в точности повторяет ключи индекса, что жёстко задаётся выражением `Object.keys(code.fileToEntities)`.
- Функция отбрасывает самозависимости и ссылки на несуществующие или внешние файлы, что принудительно фильтруется условием `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

## Как менять и что проверять

- Набор вершин графа жёстко привязан к ключам индекса файлов, что принудительно задаётся выражением `Object.keys(code.fileToEntities)`.
- Самозависимости файлов исключаются на этапе обхода сущностей, что гарантируется проверкой `depEntity.path !== entity.path`.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Распределяет заданный набор файлов по волнам генерации, вычисляя минимальный уровень для каждой компоненты сильной связности, чтобы зависимости обрабатывались строго раньше зависимых файлов.

## Что делает

- Строит граф файлов и ограничивает область вычислений только теми файлами из входного списка, которые присутствуют в этом графе.
- Выделяет компоненты сильной связности и рекурсивно вычисляет уровень каждой компоненты как максимум уровней её зависимостей плюс один.
- Формирует и возвращает массив волн, где каждая волна содержит отсортированные массивы файлов (компоненты), а сами волны упорядочены по возрастанию уровня.

## На что можно положиться

- Если файл A нециклически зависит от файла B, уровень волны A строго больше уровня волны B.
- Все файлы одной компоненты сильной связности всегда попадают в одну и ту же волну.
- Внутри волны группы файлов сортируются по первому файлу с помощью `left[0].localeCompare(right[0])`.

## От чего зависит

Зависит от `buildFileDag` (src/graph/file-dag.ts) для построения ориентированного графа файлов и от `stronglyConnectedComponents` (src/graph/file-dag.ts) для выделения компонент сильной связности.

## Кто и как использует

1. `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) вызывают функцию для получения массива волн, который затем используется для позиционирования узлов и рендеринга пирамиды зависимостей в HTML или текстовом виде.

## Чего не делает

- Область вычислений ограничена файлами, которые уже присутствуют в графе, что принудительно фильтруется выражением `files.filter((file) => dag.has(file))`.
- Сортировка групп файлов внутри одной волны опирается только на первый файл группы, что жёстко задаётся компаратором `left[0].localeCompare(right[0])`.

## Как менять и что проверять

- Входной список файлов автоматически сужается до тех путей, что уже есть в графе, что принудительно реализуется фильтром `files.filter((file) => dag.has(file))`.
- Порядок групп внутри волны определяется исключительно первым файлом каждой группы, что задаётся выражением `left[0].localeCompare(right[0])`.
