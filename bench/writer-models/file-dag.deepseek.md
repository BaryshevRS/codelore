# file-dag.ts

## Зачем это нужно

Определяет порядок обработки файлов для генерации документации: строит граф прямых файловых зависимостей и разбивает произвольный набор файлов на волны, группируя циклически связанные файлы в одну волну.

## Что делает

- Строит ориентированный граф файловых зависимостей из CodeIndex: для каждого файла из fileToEntities создаёт вершину, для каждой сущности добавляет файлы её прямых зависимостей, исключая самозависимости и ссылки на файлы вне индекса.
- Разбивает переданный набор файлов на волны генерации: фильтрует файлы, присутствующие в графе, выделяет компоненты сильной связности, присваивает каждой компоненте уровень на основе максимального уровня её зависимостей, и возвращает отсортированные волны, где циклически связанные файлы находятся в одной волне.

## На что можно положиться

- Граф не содержит петель: для любого файла его множество зависимостей не включает его самого (проверка `depEntity.path !== entity.path`).
- Волны детерминированы: группы внутри волны сортируются по первому файлу, волны — по возрастанию уровня.
- Файлы, отсутствующие в `code.fileToEntities`, никогда не появляются ни в графе, ни в волнах.

## Чего не делает

Граф файлов строится только из ключей `Object.keys(code.fileToEntities)` — файлы, отсутствующие в этом объекте, не попадают ни в граф, ни в волны. Зависимости, чья сущность не найдена в `code.entities`, ведёт на тот же файл или на файл вне графа, отбрасываются условием `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)` в `buildFileDag`. Волны вычисляются только для файлов, прошедших фильтр `dag.has(file)` в `generationWaves`; файлы, не попавшие в граф, молча игнорируются.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Строит ориентированный граф прямых файловых зависимостей из CodeIndex, исключая самозависимости и файлы вне индекса.

## Что делает

- Создаёт вершину для каждого файла из `code.fileToEntities`, инициализируя пустым множеством.
- Для каждой сущности из `code.entities` добавляет файлы её прямых зависимостей в множество файла-владельца, отфильтровывая самозависимости (`depEntity.path !== entity.path`) и зависимости к файлам, отсутствующим в графе (`dag.has(depEntity.path)`).
- Возвращает `Map<string, Set<string>>`, где ключ — файл, значение — множество файлов, от которых он напрямую зависит.

## На что можно положиться

- Возвращаемый граф содержит те же файлы, что и `code.fileToEntities`.
- Файл никогда не указывает сам на себя: проверка `depEntity.path !== entity.path`.
- Зависимость игнорируется, если сущность-зависимость не найдена в `code.entities`, если её путь совпадает с путём владельца, или если файл зависимости отсутствует в графе; условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

## Кто и как использует

`generationWaves` (src/graph/file-dag.ts) вызывает `buildFileDag`, чтобы построить DAG, который затем участвует в выделении компонент сильной связности и вычислении волн генерации. `collectDependencyDocs` (src/llm/file-pipeline.ts) вызывает `buildFileDag`, чтобы определить файлы-зависимости за пределами текущей группы, и затем формирует `DependencyDoc` с учётом лимита `DEP_DOCS_TOTAL_CAP`. `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) вызывают `buildFileDag`, чтобы построить граф для визуализации пирамиды зависимостей.

## Чего не делает

Набор вершин графа ограничен итерацией `Object.keys(code.fileToEntities)` — файлы вне объекта не попадут в результат. Зависимости отбрасываются, если сущность не найдена в `code.entities`, если её путь совпадает с путём владельца (`depEntity.path !== entity.path`), или если файл зависимости отсутствует в графе (`dag.has(depEntity.path)`); все три проверки объединены в условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

## Как менять и что проверять

1. Множество вершин графа формируется итерацией `Object.keys(code.fileToEntities)` — каждый ключ становится вершиной с пустым множеством зависимостей.
2. Самозависимости исключаются проверкой `depEntity.path !== entity.path` внутри условия `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Вычисляет минимальные волны генерации для заданного набора файлов: разбивает файлы на компоненты сильной связности и присваивает каждой компоненте уровень, гарантируя, что зависимости обрабатываются раньше зависимых файлов, а циклы объединяются в одну волну.

## Что делает

- Строит DAG с помощью `buildFileDag`, затем ограничивает область файлами, присутствующими в графе (фильтр `files.filter(file => dag.has(file))`).
- Разбивает отфильтрованные файлы на компоненты сильной связности с помощью `stronglyConnectedComponents`.
- Присваивает каждой SCC уровень (волну), рекурсивно вычисляя максимальный уровень зависимостей плюс один; SCC без зависимостей получают уровень 0.
- Возвращает массив волн, где каждая волна — массив групп файлов (SCC), отсортированных по первому файлу; сами волны отсортированы по возрастанию уровня.

## На что можно положиться

- Если файл A нециклически зависит от файла B, то волна A строго больше волны B.
- Все файлы одной SCC находятся в одной волне.
- Файлы, отсутствующие в DAG, игнорируются: фильтр `files.filter(file => dag.has(file))`.
- Внутри волны группы отсортированы по первому файлу: `left[0].localeCompare(right[0])`.
- Волны отсортированы по возрастанию уровня.

## Кто и как использует

Вызывается из `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) для получения волн генерации. Оба вызова передают индекс кода и список файлов, полученный из проекта. Результат (волны) затем визуализируется в виде пирамиды зависимостей: текстовой в `renderGraphTree` или в виде графа Cytoscape.js в `renderGraphHtml`.

## Чего не делает

Область действия ограничена файлами, присутствующими в DAG: фильтр `files.filter((file) => dag.has(file))` отбрасывает файлы без записей в `code.fileToEntities`. Сортировка волн использует первый файл каждой группы: `left[0].localeCompare(right[0])`, что не учитывает остальные файлы группы.

## Как менять и что проверять

1. Входной список файлов ограничивается файлами, присутствующими в графе: фильтр `files.filter((file) => dag.has(file))`.
2. Группы внутри волны сортируются по первому файлу: `left[0].localeCompare(right[0])`.
