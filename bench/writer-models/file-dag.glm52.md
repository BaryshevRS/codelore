# file-dag.ts

## Зачем это нужно

Превращает индекс кода в топологию обработки файлов: строит граф прямых файловых зависимостей и разбивает произвольный набор файлов на волны генерации, где циклически связанные файлы объединяются в одну группу, а зависимости обрабатываются раньше зависимых.

## Что делает

- Три функции образуют конвейер: `buildFileDag` строит DAG из `CodeIndex`, `stronglyConnectedComponents` выделяет компоненты сильной связности итеративным алгоритмом Тарьяна, `generationWaves` объединяет граф и SCC в волны генерации.
- Все функции разделяют тип `FileDag` — `Map<string, Set<string>>`, где ключ — файл, значение — множество файлов, от которых он напрямую зависит.
- `generationWaves` делегирует построение графа функции `buildFileDag` и поиск SCC — локальной функции `stronglyConnectedComponents`, не дублируя их внутреннюю логику.

## На что можно положиться

- Результат всего конвейера детерминирован: `stronglyConnectedComponents` обходит вершины в отсортированном порядке, `generationWaves` сортирует группы внутри волны по первому файлу (`left[0].localeCompare(right[0])`) и файлы внутри группы через `.sort()`.
- Файлы вне `code.fileToEntities` не появляются ни в графе, ни в волнах: `buildFileDag` создаёт вершины только из ключей этого объекта, а `generationWaves` фильтрует вход через `dag.has(file)`.

## Чего не делает

`stronglyConnectedComponents` учитывает только соседей, входящих в запрошенную область: `neighborsOf` фильтрует рёбра через `scope.has(dep)`, поэтому зависимости на файлы вне `scope` не влияют на компоненты сильной связности. Уровень SCC в `generationWaves` вычисляется только по межгрупповым рёбрам — условие `depGroup !== undefined && depGroup !== groupIndex` исключает внутригрупповые зависимости из расчёта уровня.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Строит ориентированный граф прямых файловых зависимостей из `CodeIndex`, чтобы последующие функции могли вычислять порядок обработки файлов на основе отношений между файлами, а не между сущностями.

## Что делает

- Создаёт вершину для каждого файла из `code.fileToEntities`, инициализируя пустым множеством зависимостей.
- Для каждой сущности из `code.entities` добавляет файлы её прямых зависимостей в множество файла-владельца, отфильтровывая несуществующие сущности, самозависимости и ссылки на файлы вне графа.
- Возвращает `Map<string, Set<string>>`, где ключ — файл-владелец, значение — множество файлов, от которых он напрямую зависит.

## На что можно положиться

- Возвращаемый граф содержит ровно те файлы, что являются ключами `code.fileToEntities`.
- Файл никогда не указывает сам на себя: проверка `depEntity.path !== entity.path`.
- Зависимость отбрасывается, если сущность не найдена в `code.entities`, её путь совпадает с путём владельца, или файл зависимости отсутствует в графе; условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`.

## Кто и как использует

`generationWaves` вызывает `buildFileDag` первой строкой тела, чтобы получить DAG для последующего поиска SCC и вычисления уровней волн. `collectDependencyDocs` (src/llm/file-pipeline.ts) строит граф через `buildFileDag(index.code)` и перебирает `dag.get(file) ?? []` для каждого файла из группы, собирая файлы-зависимости вне группы; затем формирует `DependencyDoc` с отсечкой по `DEP_DOCS_TOTAL_CAP`. `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) используют граф из `buildFileDag` через `collectNodes(input)` для визуализации пирамиды зависимостей — HTML-граф Cytoscape.js и текстовое дерево соответственно.

## Чего не делает

Набор вершин определяется итерацией `Object.keys(code.fileToEntities)` — файлы, не являющиеся ключами этого объекта, не попадают в граф. Ребро добавляется только при одновременном выполнении трёх проверок в условии `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`: сущность зависимости найдена в `code.entities`, её путь не совпадает с путём владельца и файл зависимости присутствует в графе.

## Как менять и что проверять

1. Несуществующие сущности-зависимости отбрасываются коротким замыканием `depEntity &&` — если `code.entities[depId]` возвращает `undefined`, ребро не добавляется.
2. Ребро на файл вне графа отсекается проверкой `dag.has(depEntity.path)` — только файлы, уже созданные как вершины на первом цикле, могут быть целью зависимости.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Вычисляет минимальные волны генерации для заданного набора файлов, гарантируя, что зависимости обрабатываются раньше зависимых, а циклически связанные файлы объединяются в одну волну.

## Что делает

- Делегирует построение графа функции `buildFileDag` и ограничивает область файлами, присутствующими в графе.
- Делегирует поиск компонент сильной связности локальной функции `stronglyConnectedComponents`, которая реализует итеративный алгоритм Тарьяна со стеком фреймов: для каждого файла назначает индекс и lowLink, обходит соседей в отсортированном порядке, обновляет lowLink через обратные рёбра и извлекает SCC из стека при совпадении lowLink с индексом.
- Присваивает каждой SCC уровень: рекурсивно вычисляет максимальный уровень зависимых SCC плюс один с мемоизацией через массив `levels`; SCC без внешних зависимостей получают уровень 0.
- Собирает волны: каждая SCC становится отсортированной группой файлов, группы помещаются в волну по уровню, волны сортируются по первому файлу группы.

## На что можно положиться

- Если файл A нециклически зависит от файла B, волна A строго больше волны B.
- Все файлы одной SCC находятся в одной волне.
- Файлы, отсутствующие в DAG, игнорируются фильтром `files.filter((file) => dag.has(file))`.
- Внутри волны группы отсортированы по первому файлу (`left[0].localeCompare(right[0])`), волны упорядочены по возрастанию уровня.

## Кто и как использует

`renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) вызывают `generationWaves` для получения упорядоченных волн генерации файлов. Результат `string[][][]` — волны по возрастанию уровня, где каждая волна содержит отсортированные группы файлов — передаётся в визуализацию пирамиды зависимостей.

## Чего не делает

Область действия ограничена файлами, присутствующими в DAG: фильтр `files.filter((file) => dag.has(file))` отбрасывает любые файлы без записи в графе. Сортировка групп внутри волны опирается только на первый файл каждой группы: компаратор `left[0].localeCompare(right[0])` не учитывает остальные файлы. Уровень SCC вычисляется только для зависимостей, принадлежащих другой группе: условие `depGroup !== undefined && depGroup !== groupIndex` исключает внутригрупповые рёбра из расчёта уровня.

## Как менять и что проверять

1. Входной список файлов ограничивается файлами, присутствующими в графе: `files.filter((file) => dag.has(file))`.
2. Внутригрупповые рёбра исключаются из расчёта уровня: `depGroup !== undefined && depGroup !== groupIndex`.
