# file-dag.ts

## Зачем это нужно

Предоставляет единую точку для вычисления порядка обработки файлов: строит ориентированный граф прямых зависимостей и разбивает произвольный набор файлов на волны, где циклически связанные файлы сгруппированы, а нециклические зависимости обрабатываются раньше зависимых.

## Что делает

— Вычисляет граф файлов (`buildFileDag`): создаёт вершины для каждого файла из `code.fileToEntities`, добавляет рёбра от прямых зависимостей сущностей, исключая самозависимости и файлы вне индекса.
— Вычисляет волны (`generationWaves`): фильтрует входной список файлов графом, выделяет компоненты сильной связности, рекурсивно назначает им уровни (0 для компонент без зависимостей, иначе max(уровни-зависимых) + 1) и возвращает волны, упорядоченные по возрастанию уровня.

## На что можно положиться

— Порядок волн и группировка детерминированы: повторный вызов с теми же аргументами возвращает идентичный результат (нет случайности, только детерминированные сортировки).
— Топологическая корректность: если файл A зависит от файла B без цикла, волна A > волны B.
— Файлы одной компоненты сильной связности гарантированно получают одинаковую волну.
— Возвращается только подмножество переданных файлов, которое присутствует в `code.fileToEntities`; остальные молча игнорируются.

## Чего не делает

Модуль не содержит внутреннего кеша. Каждый вызов `buildFileDag` и `generationWaves` строит граф и волны заново, перебирая все сущности и файлы; инкрементальные обновления не поддерживаются. Зависимости не различаются по категориям: все ссылки из `entity.directDeps` обрабатываются единообразно без учёта типа связи.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Строит Map прямых файловых зависимостей из CodeIndex, исключая самозависимости и файлы, не зарегистрированные в fileToEntities.

## Что делает

— Инициализирует вершины: для каждого файла из `Object.keys(code.fileToEntities)` создаёт запись в Map с пустым `Set<string>`.
— Для каждой сущности в `code.entities` обходит её `directDeps`; добавляет путь сущности-зависимости в множество владельца, если сущность найдена, её путь отличается от пути владельца, и этот путь есть среди ключей Map.
— Возвращает `FileDag` — `Map<string, Set<string>>`, где значение для файла — множество файлов, от которых он напрямую зависит.

## На что можно положиться

— Ключи возвращаемой Map совпадают с `Object.keys(code.fileToEntities)`.
— Ни один файл не указывает сам на себя: проверка `depEntity.path !== entity.path`.
— Зависимость игнорируется, если сущность-зависимость не найдена в `code.entities`, её путь совпадает с путём владельца, или её файл отсутствует в графе (условие `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`).

## Кто и как использует

`generationWaves` (в этом же файле) строит DAG, чтобы затем отфильтровать входные файлы по наличию в графе (`scope`), выделить компоненты сильной связности и вычислить уровни, используя `dag` для получения зависимостей каждой группы. `collectDependencyDocs` (src/llm/file-pipeline.ts) формирует список документации зависимостей: после построения DAG собирает внешние файлы-зависимости для переданного набора файлов, сортирует их и упаковывает в `DependencyDoc` с ограничением суммарного размера (`DEP_DOCS_TOTAL_CAP`). `renderGraphHtml` и `renderGraphTree` (src/cli/render-graph.ts) используют граф для определения зависимостей при построении текстовой и интерактивной визуализации пирамиды генерации.

## Чего не делает

Зависимости, чья сущность-цель отсутствует в `code.entities`, отбрасываются проверкой `depEntity` внутри условия `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`. Самозависимости исключаются сравнением `depEntity.path !== entity.path`. Файлы вне инициализированного множества вершин (полученного из `Object.keys(code.fileToEntities)`) не попадают ни в граф, ни в зависимости — для них нет рёбер, и ссылки на них игнорируются условием `dag.has(depEntity.path)`.

## Как менять и что проверять

1. Каждая вершина графа создаётся итерацией `Object.keys(code.fileToEntities)` — конструкция определяет итоговое множество файлов в результате.
2. Зависимость добавляется только при выполнении полного условия `depEntity && depEntity.path !== entity.path && dag.has(depEntity.path)`, которое одновременно отсекает отсутствующие сущности, самозависимости и несуществующие файлы.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Разбивает переданные файлы на минимальные волны генерации: выделяет компоненты сильной связности, каждой назначает уровень так, что зависимости обрабатываются раньше зависимых, а циклы объединяются в одну волну.

## Что делает

— Строит граф через `buildFileDag(code)` и ограничивает область файлами, которые есть в графе (фильтр `files.filter(file => dag.has(file))`).
— Вычисляет компоненты сильной связности с помощью `stronglyConnectedComponents(scope, dag)`.
— Рекурсивно назначает уровень каждой компоненте: 0, если нет зависимостей на другие компоненты в scope, иначе `max(levelOf(depGroup) + 1)` по всем зависимостям; мемоизация через массив `levels`.
— Собирает волны: для каждой SCC добавляет отсортированную группу файлов в волну с индексом, равным её уровню; затем сортирует волны по возрастанию уровня, а группы внутри волны — лексикографически по первому файлу.

## На что можно положиться

— Если файл A нециклически зависит от файла B, то волна A > волны B.
— Все файлы одной компоненты сильной связности попадают в одну волну.
— Файлы, не найденные в DAG (отсутствуют в `code.fileToEntities`), не включаются в результат и не влияют на уровни.
— Детерминированность: для одних и тех же `code` и `files` возвращается идентичный массив волн.

## От чего зависит

Вызывает `buildFileDag` для построения прямого графа файловых зависимостей и `stronglyConnectedComponents` для выделения компонент сильной связности (алгоритм Тарьяна).

## Кто и как использует

`renderGraphHtml` (src/cli/render-graph.ts) вызывает `generationWaves`, чтобы определить уровни файлов для построения визуализации графа: волны используются для вычисления координат узлов cytoscape. `renderGraphTree` (src/cli/render-graph.ts) получает волны для вывода текстовой пирамиды зависимостей: номера волн и статус документирования каждой SCC.

## Чего не делает

Область действия ограничена файлами, присутствующими в DAG: выражение `files.filter((file) => dag.has(file))` отбрасывает файлы без записей в `code.fileToEntities` до формирования SCC. Сортировка групп внутри волны использует только первый файл каждой группы — `left[0].localeCompare(right[0])`, что не учитывает остальные элементы SCC и может повлиять на итоговый порядок при совпадении первого элемента.

## Как менять и что проверять

1. Файлы вне графа исключаются фильтром `files.filter((file) => dag.has(file))`, применённым до группировки.
2. Итоговая сортировка групп в волне выполняется выражением `left[0].localeCompare(right[0])`, определяющим детерминированный, но ограниченный лексикографический порядок SCC.
