# Per-block dependency invalidation

## Проблема

`collectDepDocStaleBlocks` (`src/service/stale-detection.ts:83`) считает один отпечаток
на весь файл: `dependencyDocsFingerprint(collectDependencyDocs(index, [file]))` — хеш от
доков **всех** зависимостей разом. Изменился любой из них — протухают все терминальные
блоки всех секций этого файла.

Замер: подмена пяти отпечатков в `src/service/prepare-docs.ts` дала 60 тумбстоунов в
`src/service/codelore-service.ts` (29 секций, 92 kB). Каскад раздул 5 блоков в 99.

`gateDepDocsCascade` существует, чтобы это смягчать: отдельный LLM-проход перепроверяет
зависимых и переставляет штампы, лишь бы не переписывать. В прогоне на 63 минуты он занял
26 минут 44 секунды — 42%. То есть за грубую инвалидацию платят отдельной дорогой фазой.

## Что уже есть

Писатель заполняет `refs` у каждого блока, и промпт требует именно то, что нужно
(`src/llm/file-writer.ts:101`):

> the entity ids, file paths, or dependency source paths the block's statements rely on.
> Allowed refs are exactly: the section's own entity id, ids listed in that section's
> callers and dependencyEntityIds, and **dependencyDocs sourcePaths**.

`doc-validator.ts` их проверяет. `DependencyDoc` (`src/llm/file-writer.ts:40`) ключуется
по `sourcePath` — по тому же, что блок называет.

Но `refs` теряются: `WrittenBlock.refs` не переносится в `GeneratedBlock`
(`src/llm/file-pipeline.ts:1417`, `src/llm/domain-pipeline.ts:144`), и в
`DocStateBlock` такого поля нет. Ни у одного из 254 блоков проекта `refs` не сохранены.

## Шаги

### 1. Донести refs до состояния

- `GeneratedBlock` (`src/types.ts:325`) — добавить `refs?: string[]`.
- `src/llm/file-pipeline.ts:1417` и `src/llm/domain-pipeline.ts:144` — передавать `refs: block.refs`.
- `DocStateBlock` (`src/types.ts:175`) — добавить `refs?: string[]`.
- `mergeGeneratedBlocksIntoSection` (`src/service/section-rewrite.ts:96`) — сохранять их
  рядом с `scores`.

`DOC_STATE_VERSION` не трогать: поле необязательное, его отсутствие означает «неизвестно»
и включает старое поведение. Существующие состояния продолжают работать без миграции.

**Проверка:** после одного `generate --force --file <небольшой файл>` в JSON состояния у
блоков непустые `refs`.

### 2. Отпечаток зависимостей на блок

- Функция, считающая `dependencyDocsFingerprint` только по тем `DependencyDoc`, чей
  `sourcePath` назван в `refs` блока.
- Хранить результат на блоке (`DocStateBlock.depDocsFingerprint`), проставлять при записи
  там же, где `fingerprint`.

**Проверка:** юнит-тест — две секции одного файла с разными `refs`; изменение одной
зависимости меняет отпечаток только у той, что на неё ссылается.

### 3. Использовать его в детекторе

В `collectDepDocStaleBlocks`:

- блок **с** `refs` — сравнивать его собственный отпечаток с пересчитанным по его же `refs`;
- блок **без** `refs` — сегодняшнее файловое поведение (запасной путь для старых состояний);
- блок с **пустым** массивом `refs` (выведен только из своего исходника) — по `depDocs`
  не протухает никогда.

**Проверка:** существующие тесты проходят без правок; новый тест — блок, чьи `refs`
указывают на другую зависимость, не помечается при изменении первой.

### 4. Измерить сжатие каскада — это ворота, а не формальность

Повторить замер: подменить пять отпечатков в `prepare-docs.ts`, посчитать тумбстоуны в
`codelore-service.ts` до и после.

**Критерий:** число должно заметно упасть с 60. Если не упало — значит писатель
перечисляет в `refs` всё подряд, и вся затея не работает. Тогда останавливаться здесь, а
не выпиливать гейт.

Риск именно тут: `refs` порождает модель. Валидатор отбрасывает несуществующие ссылки,
но не защищает от слишком широких. Пока шаг 4 не пройден, шаг 5 запрещён.

### 5. Только потом — пересмотреть gateDepDocsCascade

Гейт остаётся, пока в проекте есть блоки без `refs`: для них нужна старая компенсация.
Когда покрытие станет высоким — замерить, очищает ли он ещё хоть что-нибудь, и удалять
только по факту, а не по ожиданию.

## Как приходит точность

`refs` знает только писатель в момент генерации — вывести их из существующего состояния
нельзя, поэтому дешёвой миграции нет. Блок получает точную инвалидацию, когда его
перепишут в очередной раз. Горячие файлы сконвертируются в первые же прогоны: первый
каскад по `codelore-service.ts` перепишет 60 блоков и все 60 снабдит `refs`. Тихие файлы
останутся на грубом правиле надолго, и это принято сознательно — платить часы за
`generate --force` по всему проекту ради того, что случится бесплатно, незачем.
