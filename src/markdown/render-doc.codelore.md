# renderDoc

## Зачем это нужно

Формирует итоговый Markdown-документ, объединяя результаты рендера каждой секции из state.sectionOrder, и возвращает пустую строку при пустом списке секций.

## Что делает

- Перебирает state.sectionOrder, для каждого идентификатора получает секцию из state.sections и пропускает отсутствующие секции.
- Делегирует рендер каждой секции функции renderSection с переданными config и language.
- Соединяет результаты рендера двойным переводом строки и добавляет завершающий перевод строки.
- Возвращает пустую строку при пустом state.sectionOrder.

## На что можно положиться

- Порядок секций в итоговом документе соответствует порядку их идентификаторов в state.sectionOrder.
- При пустом state.sectionOrder возвращает пустую строку.
- Функция не изменяет переданные объекты state и config.

## Кто и как использует

DocStateStorage.renderAndPersist вызывает renderDoc(state, this.config) для канонического языка и renderDoc(state, this.config, language) для каждого языка из config.docs.translations. После рендера результат записывается в файл state.docPath (для канонического) и в файл с суффиксом языка (для переводов).

## Чего не делает

- При `state.sectionOrder.length === 0` возвращается пустая строка без завершающего `\n` — конструкция `return ""`.
- Секция, отсутствующая в `state.sections`, молча пропускается — проверка `if (!section) { continue; }` не генерирует ошибку.
- Дубликаты идентификаторов в `state.sectionOrder` приводят к повторному рендеру одной и той же секции, без дедупликации.

## Как менять и что проверять

- Пустой `sectionOrder` возвращает пустую строку без завершающего `\n`. Конструкция: `if (state.sectionOrder.length === 0) { return ""; }`. Тест на пустой документ.
- Секции разделяются двумя переводами строки и завершаются одним `\n`. Конструкция: `` return `${parts.join("\n\n")}\n`; ``. Тест на документ с несколькими секциями.

# renderSection

## Зачем это нужно

Формирует Markdown-подраздел из состояния одной секции, управляя порядком и отображением блоков (свежие и устаревшие).

## Что делает

- Формирует заголовок секции и определяет заголовки блоков для нужного языка.
- Упорядочивает блоки (сначала section.blockOrder, затем BLOCK_IDS) и для каждого проверяет rendered.
- Для свежих блоков выводит подзаголовок и тело; для устаревших группирует в staleCallout по паре (staleReason, staleSince).
- Игнорирует блоки с rendered: false.

## На что можно положиться

- Результат всегда начинается с заголовка секции, даже если ни один блок не выведен.
- Stale-блоки выводятся в виде одного callout на группу (одинаковые staleReason и staleSince), их тела не отображаются.
- Пропущенные блоки (rendered: false) не выводятся и не влияют на порядок.
- Функция не изменяет переданные section и config.

## Кто и как использует

renderDoc вызывает renderSection для каждой секции из sectionOrder. CodeloreService.readDocSection вызывает renderSection для одной секции по идентификатору после загрузки её состояния из хранилища. Внутри: определяется translationLanguage — если язык является переводным, используются локализованные заголовки блоков. Для каждого блока из orderedRenderableBlocks: если block.rendered === false, блок пропускается; если block.staleSince задан, блок помещается в группу stale и не выводится; иначе выводится подзаголовок из headings[blockId] и тело через blockBody. blockBody проверяет актуальность перевода через translationSourceFingerprint; при устаревании или отсутствии перевода вставляется translationPendingCallout.

## Чего не делает

- При отсутствии блока в `section.blocks` обращение `section.blocks[blockId]` даёт `undefined`, и блок молча пропускается (проверка `!block?.rendered`).
- Группировка stale-блоков использует ключ `` `${block.staleReason ?? ""}\x00${block.staleSince}` ``; если `staleReason` равен `undefined`, пустая строка может сгруппировать блоки с разными причинами при одинаковой дате.
- Не проверяется, что идентификаторы в `section.blockOrder` присутствуют в `BLOCK_IDS` — несуществующие id игнорируются в `orderedRenderableBlocks`.

## Как менять и что проверять

- Stale-блоки группируются по ключу `` `${block.staleReason ?? ""}\x00${block.staleSince}` ``. Изменение разделителя или логики группировки изменит отображение callout. Тест на несколько stale-блоков с одинаковой датой.
- Определение переводного языка: `const translationLanguage = isTranslationLanguage(language, config) ? language : undefined;`. Изменение предиката `isTranslationLanguage` повлияет на использование локализованных заголовков и вызов blockBody. Тест на переводной язык.
