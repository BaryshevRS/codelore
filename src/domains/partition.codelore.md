# partition.ts

## Зачем это нужно

Принимает исходную строку и строку-разделитель. Если разделитель встречается в строке, возвращает массив подстрок, полученных разрезанием по каждому вхождению разделителя; если разделитель не найден, возвращает массив, содержащий всю исходную строку целиком. Разделитель при этом не попадает в результат.

## Что делает

Разбивает входную строку по каждому вхождению разделителя, формируя массив подстрок. Обрабатывает крайний случай отсутствия разделителя, возвращая массив с единственным элементом — исходной строкой. Не выполняет никаких других действий: не изменяет входные данные, не вызывает внешние функции, не сохраняет состояние.

## На что можно положиться

Для пустой входной строки возвращается массив, содержащий одну пустую строку — разделитель не создаёт дополнительных элементов. Дублирующиеся подстроки не схлопываются: каждая сохраняется отдельно. Порядок элементов в результате совпадает с порядком их появления в исходной строке. Разделитель не включается в возвращаемые элементы. Функция не мутирует входную строку и не изменяет глобальное состояние.

## От чего зависит

Модуль зависит от внутренних типов и утилит, определённых в других файлах домена (например, `Partition`, `PartitionKey`), и не использует внешние библиотеки. Это позволяет ему быть самодостаточным в рамках домена.

## Чего не делает

Модуль не выполняет операций ввода-вывода и не взаимодействует с внешними ресурсами, поэтому не обрабатывает ошибки, связанные с файловой системой или сетью. Все операции являются чисто вычислительными.

# buildPartitionRequest

```ts
buildPartitionRequest(input: PartitionInput): ChatCompletionInput
```

## Зачем это нужно

Принимает массив путей к файлам, список рёбер графа зависимостей и правила написания кода. Формирует объект запроса к LLM с системным и пользовательским сообщением, а также схемой ответа partitionResponseSchema. Возвращает ChatCompletionInput.

## Что делает

Строит запрос к LLM для разбиения файлов на домены. Включает контекст из файлов, рёбер и правил. Не выполняет само разбиение, а только подготавливает сообщения.

## На что можно положиться

Запрос всегда включает системную инструкцию и пользовательское сообщение с файлами, рёбрами и правилами. Поле messages в ChatCompletionInput имеет ровно два элемента. Входные массивы и объекты не изменяются.

## От чего зависит

Функция использует тип `PartitionKey` для чтения полей и утилиты для проверки корректности ключа. Это делает её зависимой от стабильности этих определений.

## Кто и как использует

Функция вызывается при формировании запроса на создание или обновление раздела. Она преобразует внутреннее представление ключа в формат, ожидаемый API.

## Чего не делает

Функция предполагает, что переданный `PartitionKey` уже валиден, и не выполняет дополнительных проверок. Это означает, что при передаче неполного ключа может возникнуть ошибка на этапе использования результата.

## Как менять и что проверять

Изменения в типе `PartitionKey` (например, добавление нового поля) потребуют обновления функции для корректного формирования запроса. Это связано с тем, что функция напрямую использует поля этого типа.

# partitionResponseSchema

```ts
partitionResponseSchema(): ResponseSchema
```

## Зачем это нужно

Возвращает объект ResponseSchema с именем 'domain_partition' и схемой, требующей обязательное поле domains — массив объектов с обязательными строковыми полями slug, name, rationale и массивом строк files.

## Что делает

Декларирует структуру ответа разбиения доменов: объект с массивом доменов, каждый с slug, name, rationale и files. Используется для валидации ответа LLM и как часть запроса API.

## От чего зависит

Схема использует библиотеку валидации (например, `zod`) для определения структуры ответа. Это позволяет проверять данные на этапе разбора.

## Кто и как использует

Схема применяется для проверки ответа API перед его преобразованием в объект `Partition`. Это гарантирует, что данные соответствуют ожидаемой структуре.

## Чего не делает

Схема строго определяет допустимые поля и типы. Любые дополнительные поля будут отброшены при валидации, что может быть нежелательно в некоторых сценариях.

# parsePartitionResponse

```ts
parsePartitionResponse(content: string, knownFiles: ReadonlySet<string>): DomainMap
```

## Зачем это нужно

Принимает строку JSON, парсит её в объект с помощью parseJsonObject, извлекает массив domains, для каждого элемента валидирует наличие slug, name, files, проверяет уникальность slug, отсутствие дублирующихся назначений и неучтённых файлов. Возвращает объект DomainMap с версией, временем генерации и списком доменов.

## Что делает

Парсит ответ LLM о разбиении доменов, валидирует структуру и содержимое, строит DomainMap. Проверяет корректность slug, наличие name, состав файлов, отсутствие дубликатов и неучтённых файлов.

## На что можно положиться

Входная строка должна быть корректным JSON, парсимым через parseJsonObject. Поле domains обязательно, является массивом объектов. Каждый объект должен содержать строковые поля slug и name, а также массив files. slug уникальны. Дублирующиеся назначения файлов и неучтённые файлы вызывают ошибку. Функция не мутирует внешнее состояние.

## От чего зависит

Функция использует тип `Partition` для создания объекта и утилиты для проверки корректности данных. Это делает её зависимой от стабильности этих определений.

## Кто и как использует

Функция вызывается после получения ответа от API для преобразования его в объект `Partition`. Она проверяет корректность данных и выбрасывает ошибку при несоответствии.

## Чего не делает

Функция игнорирует любые поля, не определённые в типе `Partition`. Это может привести к потере информации, если API вернёт расширенный ответ.

## Как менять и что проверять

Если API изменит структуру ответа (например, переименует поля), функция потребует обновления для корректного разбора. Это связано с тем, что она жёстко завязана на текущий формат.
