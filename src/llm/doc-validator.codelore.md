# validateFileWrite

## Зачем это нужно

Проверяет сгенерированные блоки документации на соответствие структурным правилам и контексту секции.

## Что делает

- Не исправляет нарушения — только возвращает список `DocViolation`.
- Не проверяет семантическую корректность текста, только структурные правила (ссылки, длина, существование путей).
- Не проверяет пути, не соответствующие шаблону `MENTIONED_PATH_PATTERN`.
- Делегирует проверку существования путей внешнему колбэку `fileExists`.

## На что можно положиться

- Возвращает всегда массив (пустой при отсутствии нарушений).
- Не бросает исключения.
- Секции из `result`, отсутствующие в `sections`, игнорируются.
- Для проверки длины текста используется константа `MAX_BLOCK_CHARS` (2500).

## Кто и как использует

Вызывается из файла [`src/llm/file-pipeline.ts`](file-pipeline.codelore.md) после завершения генерации файлов. Функция перебирает секции в `result`. Для каждой секции проверяется длина текста каждого блока, валидность ссылок (`validateRef`), соответствие ролей ссылок (`validateRefRole`), существование упомянутых путей (`validateMentionedPaths`) и символов (`validateMentionedSymbols`). Нарушения собираются в массив и возвращаются вызывающему коду для анализа качества генерации.

## Чего не делает

- Проверка существования путей (`validateMentionedPaths`) активна только при переданном колбэке `fileExists`; при его отсутствии пути не проверяются.
- Шаблон `MENTIONED_PATH_PATTERN` не покрывает пути без расширения или с нестандартными расширениями.
- `validateRefRole` выполняется исключительно для блока `dependencies` — условие `if (blockId !== "dependencies") { return []; }`.
- Не проверяется, что каждая ссылка из `refs` упоминается в тексте блока — проверяются только существование ссылки и совпадение символов в тексте со списком разрешённых.

## Как менять и что проверять

1. Игнорирование отсутствующих секций — условие `if (!section) { continue; }` предотвращает ошибки при неполном наборе секций.
2. Ограничение длины текста блока — константа `const MAX_BLOCK_CHARS = 2500` и проверка `block.text.length > MAX_BLOCK_CHARS`.

## От чего зависит

- `BlockId` (`src/markdown/block-ids.ts`) — тип идентификатора блока.
- `FileWriteResult`, `FileWriteSection` ([`src/llm/file-writer.ts`](file-writer.codelore.md)) — типы результата и секции файла.

# allowedRefsForSection

```ts
allowedRefsForSection(section: FileWriteSection, input: Pick<ValidateFileWriteInput, "dependencyDocPaths" | "groupFiles">): Set<string>
```

## Зачем это нужно

Вычисляет множество идентификаторов, которые разрешено указывать в `refs` блока документации для данной секции.

## Что делает

- Добавляет идентификатор сущности секции (`section.entity.id`) и, если из него извлекается путь к файлу, добавляет этот путь в двух формах: как есть и с префиксом `file:`.
- Для каждого вызывающего (`section.callers`) добавляет его идентификатор и путь к файлу.
- Для каждой прямой зависимости (`section.dependencyEntityIds`) добавляет идентификатор зависимости и, если из него извлекается путь, добавляет этот путь в двух формах.
- Добавляет все пути из `input.dependencyDocPaths` и `input.groupFiles`, каждый в двух формах: как есть и с префиксом `file:`.

## На что можно положиться

- Возвращаемое множество всегда содержит как минимум идентификатор сущности секции (`section.entity.id`).
- Функция никогда не бросает исключения при любых входных данных.
- Не модифицирует ни один из переданных объектов.

## Кто и как использует

1. [`validateFileWrite`](#validatefilewrite) (`src/llm/doc-validator.ts`) для каждой секции вызывает `allowedRefsForSection`, затем использует полученное множество для проверки ссылок через `validateRef` и `validateMentionedSymbols`.
2. [`buildRepairRequest`](file-pipeline.codelore.md#buildrepairrequest) (`src/llm/file-pipeline.ts`) для каждой секции с нарушениями вызывает `allowedRefsForSection` и включает отсортированный список разрешённых ссылок в промпт ремонта.

## Как менять и что проверять

- Для каждого вызывающего (`section.callers`) в множество добавляются и его идентификатор, и путь к файлу. Конструкт: `allowed.add(caller.id); allowed.add(caller.path);` внутри цикла `for (const caller of section.callers)`.
- Каждый путь, добавляемый в множество (из зависимостей, вызывающих, собственной сущности, dependencyDocPaths, groupFiles), дублируется с префиксом `file:`. Конструкт: `allowed.add(path); allowed.add(`file:${path}`);` (например, в блоке обработки зависимостей).

# buildEntityNameToIds

```ts
buildEntityNameToIds(entities: Record<string, { name: string }>): Map<string, string[]>
```

## Зачем это нужно

Создаёт обратный индекс для поиска идентификаторов сущностей по имени в процессе валидации упомянутых символов.

## Что делает

- Возвращает `Map`, где каждому имени сопоставлен массив из одного или нескольких идентификаторов сущностей.
- Не проверяет корректность входных данных — предполагает, что `entities` — корректная запись.
- Не модифицирует входной объект.

## На что можно положиться

- Возвращаемый `Map` содержит только ключи, являющиеся полным именем сущности или частью после последней точки (если точка присутствует).
- Массивы идентификаторов для одного ключа не содержат дубликатов (проверка `!ids.includes(id)` во внутренней функции `add`).
- Функция не бросает исключения при любом входе.
- Не модифицирует входной объект `entities`.

## Кто и как использует

Вызывается из [`src/llm/file-pipeline.ts`](file-pipeline.codelore.md) для построения обратного индекса имён сущностей.

## Чего не делает

The function registers an alias only for the segment after the last dot when that segment is non-empty; a name ending with a dot (e.g. `"foo."`) gets no alias because the guard `dot < entity.name.length - 1` fails. The alias is always the full name plus the last segment, never an intermediate segment; a name with multiple dots (e.g. `"a.b.c"`) yields only `"a.b.c"` and `"c"`, not `"b"`.

## Как менять и что проверять

1. При наличии точки в имени сущности в индекс добавляется как полное имя, так и часть после последней точки. Конструкт: `const dot = entity.name.lastIndexOf("."); if (dot >= 0 && dot < entity.name.length - 1) { add(entity.name.slice(dot + 1), id); }`.
2. Массивы идентификаторов для одного имени не содержат дубликатов. Конструкт: проверка `!ids.includes(id)` во внутренней функции `add`.
