# writeGenerationDebug

```ts
writeGenerationDebug(input: {
  statePath: string;
  entry: GenerationDebugEntry;
  phase?: string;
}): Promise<{ debugPath: string }>
```

## Зачем это нужно

Атомарная запись отладочного JSON-файла с данными о генерационном прогоне.

## Что делает

- Вычисляет целевой путь отладочного файла через [`generationDebugPathForStatePath`](#generationdebugpathforstatepath) и возвращает его в `{ debugPath }` независимо от того, включена ли отладка.
- Если отладка выключена (переменная окружения `CODELORE_DEBUG` пуста или отсутствует), завершает работу сразу после вычисления пути, не создавая файлов и не изменяя файловую систему.
- При включённой отладке рекурсивно создаёт родительскую директорию, сериализует `entry` в JSON с отступом 2 и завершающим переводом строки, пишет результат во временный файл с уникальным именем и атомарно заменяет им целевой файл.

## На что можно положиться

- При выключенной отладке файл не создаётся и не изменяется; возвращается тот же `debugPath`, который был бы использован при записи.
- При включённой отладке запись атомарна: данные сначала попадают в уникальный временный файл `${debugPath}.${process.pid}.${Math.random().toString(36).slice(2, 8)}.tmp`, затем `rename` заменяет целевой файл; читатель видит либо старый, либо новый полный файл.
- Сериализация всегда `${JSON.stringify(input.entry, null, 2)}` с завершающим переводом строки в кодировке UTF-8.
- `debugPath` детерминированно получается из `statePath` заменой суффикса `.json`: без `phase` — `.generation-debug.json`, с `phase` — `.generation-debug.${phase}.json`; если суффикса `.json` нет, путь остаётся без изменений.
- Ошибки файловой системы не перехватываются и пробрасываются вызывающему.

## От чего зависит

[`generationDebugPathForStatePath`](#generationdebugpathforstatepath) (`src/llm/generation-debug.ts`) — вычисляет путь отладочного файла на основе `statePath` и необязательной `phase`.
`generationDebugEnabled` (`src/llm/generation-debug.ts`) — проверяет, включена ли отладка через переменную окружения `CODELORE_DEBUG`.

## Кто и как использует

Вызывается из `generateFileGroup` ([`src/llm/file-pipeline.ts`](file-pipeline.codelore.md)) через `debugSink.writeFinal` — это последний шаг пайплайна генерации, сохраняющий итоговую отладочную запись после завершения всех чанков. `debugSink` создаётся вызовом `createDebugSink`, который передаёт `input`, `sections`, `dependencyDocs`, `llmStages` и `docSections`; `writeFinal` дополняет запись нарушениями, исправленными нарушениями, записанными блоками и сохранёнными блоками, затем вызывает `writeGenerationDebug`. Функция вычисляет `debugPath` через [`generationDebugPathForStatePath(statePath, phase)`](#generationdebugpathforstatepath), проверяет `generationDebugEnabled()` и, если отладка выключена, сразу возвращает `{ debugPath }` без операций ввода-вывода.

## Чего не делает

Не обрабатывает ошибки ввода-вывода — `mkdir`, `writeFile` и `rename` пробрасывают исключения вызывающему без перехвата.
Потокобезопасность не гарантируется: параллельные вызовы с одинаковым `statePath` и `phase` приведут к гонке записи, поскольку временный файл включает `process.pid` и случайную строку, но целевой путь одинаков.

## Как менять и что проверять

- Формат сериализации зафиксирован вызовом `JSON.stringify(input.entry, null, 2)` — изменение отступов или удаление завершающего перевода строки `\n` сломает инструменты, читающие эти файлы через `JSON.parse`.
- Атомарность записи обеспечивается связкой `writeFile` во временный файл + `rename` — замена на прямую запись в целевой файл приведёт к тому, что читатель может увидеть неполный JSON.
- Имя временного файла строится как `${debugPath}.${process.pid}.${Math.random().toString(36).slice(2, 8)}.tmp` — изменение схемы именования может нарушить уникальность при параллельных вызовах.
- Проверка `generationDebugEnabled()` через `if (!generationDebugEnabled())` — удаление этой проверки приведёт к созданию файлов даже при выключенной отладке.

# generationDebugPathForStatePath

## Зачем это нужно

Преобразование пути состояния в путь отладочного файла с заменой расширения `.json` на отладочный суффикс с учётом фазы.

## Что делает

Не обращается к файловой системе.
Не валидирует путь.
Заменяет только завершающий суффикс `.json` в конце строки.

## На что можно положиться

Если `statePath` заканчивается на `.json`, возвращается строка с заменой `.json` на отладочный суффикс.
Если не заканчивается, возвращается без изменений.
Функция чистая — не зависит от глобального состояния и не мутирует входные данные.

## Кто и как использует

Вызывается из [`writeGenerationDebug`](#writegenerationdebug) (тот же файл) для вычисления целевого пути отладочного файла. Заменяет суффикс `.json` в конце `statePath` на отладочный суффикс (учитывая необязательную `phase`).

## Чего не делает

Не обрабатывает пути, не заканчивающиеся на `.json` — возвращает без изменений.
Замена только суффикса `.json` в конце строки, не заменяет `.json` в середине.
Регистрозависима (не заменит `.JSON`).

# buildGenerationDebugEntry

## Зачем это нужно

Создание сжатого отладочного среза генерационного прогона для записи в `.generation-debug.json`.

## Что делает

- Копирует поля `runId`, `timestamp`, `command`, `provider`, `model`, `docPath`, `files` без изменений.
- Преобразует `sections` и `dependencyDocs` в сокращённое представление (идентификаторы, размеры). Оригинальное содержимое не сохраняется.
- Делегирует вычисление статистики текста LLM-этапов внутренней функции `mapLlmStages`.
- Включает необязательные поля `violations`, `violationsAfterRepair`, `error` только при наличии непустых значений (для массивов — если длина > 0).

## На что можно положиться

- Поле `version` всегда равно 4.
- `writtenBlocks` и `keptBlocks` всегда присутствуют в результате (при отсутствии во входе — пустой объект и пустой массив).
- `sections` и `dependencyDocs` всегда массив — даже если входные массивы пусты.
- Все обязательные поля результата всегда присутствуют (перечислены в типе `GenerationDebugEntry`).

## Кто и как использует

Вызывается из `generateFileGroup` ([`src/llm/file-pipeline.ts`](file-pipeline.codelore.md)) после обработки всех чанков каждого файла. `llmStages` наполняется через `debugSink` в процессе генерации. Результат передаётся в [`writeGenerationDebug`](#writegenerationdebug) для сохранения в `.generation-debug.json`.

## Чего не делает

- Не проверяет структуру объектов в `llmStages` — пустая запись или отсутствие поля `messages` вызывает необработанное исключение в `mapLlmStages`.
- Поля `dependencyDocs.chars` вычисляются через `JSON.stringify(doc.sections).length`, что может не соответствовать точному числу символов в исходных секциях (из-за сериализации).
- Опциональные поля включаются по условию `length > 0`, а не по наличию свойства — пустой массив `[]` исключается, что может быть неочевидно для вызывающего (если требуется явно указать «без нарушений»).
