# file-dag.ts

## Зачем это нужно

Превращает индекс сущностей проекта в файловый граф зависимостей и раскладывает выбранные файлы по волнам генерации, где каждая волна содержит группы файлов, которые можно документировать одновременно, потому что все их зависимости лежат в более нижних волнах.

## Что делает

- [`buildFileDag`](#buildfiledag) переводит сущностные зависимости в файловые: каждый файл получает множество файлов, от которых он зависит, с отбрасыванием ссылок внутри одного файла и на файлы, отсутствующие в индексе.
- `stronglyConnectedComponents` находит циклы в файловому графе итеративным алгоритмом Тарьяна, группируя взаимно зависимые файлы в одну компоненту.
- [`generationWaves`](#generationwaves) присваивает каждой компоненте уровень (волну) по максимальному уровню её зависимостей и собирает компоненты одного уровня в массивы групп файлов.

## На что можно положиться

- Порядок обхода детерминирован: `stronglyConnectedComponents` сортирует корни и соседей, а [`generationWaves`](#generationwaves) сортирует файлы внутри группы и группы внутри волны по `localeCompare`.
- Файлы, переданные в [`generationWaves`](#generationwaves), но отсутствующие в DAG, молча отбрасываются фильтром `files.filter((file) => dag.has(file))`.
- Циклические зависимости не вызывают ошибку: файлы в одном цикле попадают в одну сильно связную компоненту и обрабатываются как единая группа.

## Чего не делает

Рёбра на файлы вне запрошенного набора невидимы для волновой разметки: `neighborsOf` в `stronglyConnectedComponents` отсекает их через `scope.has(dep)`, поэтому уровень волны не учитывает зависимости на файлы, не переданные в `files`. DAG хранит только прямые зависимости — итерация `entity.directDeps` в [`buildFileDag`](#buildfiledag) не раскрывает транзитивные связи, и потребителям, которым нужно замыкание, приходится обходить DAG самостоятельно.

# buildFileDag

```ts
buildFileDag(code: CodeIndex): FileDag
```

## Зачем это нужно

Создаёт файловый граф зависимостей из сущностного индекса, чтобы downstream-потребители могли работать на уровне файлов, а не отдельных сущностей.

## Что делает

- Заводит пустую запись в Map для каждого файла из `code.fileToEntities`.
- Проходит по всем сущностям и добавляет в множество зависимостей файла те файлы, на которые ссылаются `directDeps`, пропуская ссылки на несуществующие сущности, на свой собственный файл и на файлы вне индекса.

## На что можно положиться

- Каждый файл из `code.fileToEntities` получает запись в DAG, даже если у него нет зависимостей — значение будет пустым `Set`.
- Самоссылки (зависимость сущности от другой сущности в том же файле) не попадают в DAG благодаря проверке `depEntity.path !== entity.path`.
- Зависимости на сущности, чьи файлы отсутствуют в `code.fileToEntities`, отбрасываются проверкой `dag.has(depEntity.path)`.
- Возвращённый Map не содержит записей для файлов, которых нет в `code.fileToEntities`.

## Кто и как использует

[`generationWaves`](#generationwaves) (в том же файле) вызывает `buildFileDag(code)` первым шагом и использует возвращённый DAG для фильтрации области и построения волн. [`collectDependencyDocs`](../llm/file-pipeline.codelore.md#collectdependencydocs) (src/llm/file-pipeline.ts) строит DAG через `buildFileDag(index.code)`, перебирает `dag.get(file) ?? []` для каждого запрошенного файла и собирает файлы-зависимости вне целевой группы, чтобы подтянуть для них документацию с ограничением по `DEP_DOCS_TOTAL_CAP`. `renderGraphHtml` и `renderGraphTree` ([src/cli/render-graph.ts](../cli/render-graph.codelore.md)) обращаются к DAG для отрисовки узлов и рёбер графа зависимостей — в виде HTML-страницы и текстового дерева соответственно.

## Чего не делает

DAG содержит только прямые зависимости: итерация `entity.directDeps` не раскрывает транзитивные связи, поэтому потребителям, которым нужно замыкание по зависимостям, приходится обходить DAG самостоятельно.

## Как менять и что проверять

- Инвариант «нет самоссылок» обеспечивается выражением `depEntity.path !== entity.path` в цикле по `directDeps`.
- Инвариант «каждый файл из `fileToEntities` получает запись» обеспечивается вызовом `dag.set(file, new Set())` в первом цикле `for (const file of Object.keys(code.fileToEntities))`.

# generationWaves

```ts
generationWaves(code: CodeIndex, files: string[]): string[][][]
```

## Зачем это нужно

Раскладывает файлы по волнам генерации так, чтобы документацию можно было создавать снизу вверх: каждая волна содержит группы файлов, все зависимости которых лежат в более ранних волнах.

## Что делает

- Строит файловый DAG через [`buildFileDag`](#buildfiledag) и фильтрует запрошенные файлы до тех, что присутствуют в DAG.
- Делегирует поиск сильно связных компонент локальной функции `stronglyConnectedComponents`, затем вычисляет уровень каждой компоненты рекурсивно с мемоизацией: уровень равен максимуму из уровней зависимых компонент плюс один.
- Собирает компоненты одного уровня в волны и сортирует файлы внутри каждой группы и группы внутри волны для детерминированного вывода.

## На что можно положиться

- Файлы из `files`, отсутствующие в DAG, молча отбрасываются и не появляются в результате.
- Внутри одной волны группы отсортированы по первому файлу группы через `localeCompare`.
- Зависимости внутри одной сильно связной компоненты не учитываются при расчёте уровня — проверка `depGroup !== groupIndex` исключает их.

## От чего зависит

[`buildFileDag`](#buildfiledag) (в том же файле) — строит файловый DAG из индекса сущностей. `stronglyConnectedComponents` (локальная функция в том же файле) — находит сильно связные компоненты в файловому графе.

## Кто и как использует

`renderGraphHtml` ([src/cli/render-graph.ts](../cli/render-graph.codelore.md)) вызывает `generationWaves` и формирует HTML-визуализацию графа зависимостей, размещая узлы по волнам. `renderGraphTree` (src/cli/render-graph.ts) вызывает `generationWaves` и выводит текстовое дерево генерации, группируя файлы по волнам от нижних к верхним.

## Чего не делает

Рёбра на файлы вне `scope` невидимы для волновой разметки: `neighborsOf` в `stronglyConnectedComponents` отсекает их через `scope.has(dep)`, поэтому уровень волны не учитывает зависимости на файлы, не переданные в параметре `files`.

## Как менять и что проверять

- Мемоизация уровня каждой компоненты обеспечивается проверкой `levels[groupIndex] >= 0` в `levelOf` — повторный вызов возвращает уже вычисленное значение.
- Детерминированный порядок файлов внутри группы обеспечивается вызовом `[...groups[i]].sort()` перед добавлением в волну.
