## Состав

* [Отпечатки блоков документации](/docs/docs/domains/block-fingerprinting#отпечатки-блоков-документации) — Подсистема вычисляет два типа отпечатков блоков документации: по фасетам принадлежащих блоку сущностей — чтобы обнаружить изменения в коде, и по исходному телу блока — чтобы определить, устарел ли перевод.
* [Граф зависимостей и влияние изменений](/docs/docs/domains/change-impact-graph#граф-зависимостей-и-влияние-изменений) — Преобразует унифицированный diff в структурированные данные об изменениях, строит по сущностному индексу файловый граф зависимостей с волнами генерации и вычисляет затронутые секции документации по переданным именам сущностей.
* [Точка входа CLI](/docs/docs/domains/cli-entrypoint#точка-входа-cli) — Запускает CLI-инструмент Codelore: разбирает глобальные аргументы, выбирает команду и передаёт управление либо `CodeloreService`, либо `startStdioServer`.
* [Индексация кода и документации](/docs/docs/domains/code-doc-indexing#индексация-кода-и-документации) — Подсистема строит два независимых индекса — код-индекс для экспортированных сущностей и док-индекс для секций документации — и выдаёт системе быстрый поиск по идентификатору, файлу и сущности без прямого обращения к файловой системе или хранилищу состояний.
* [Анализ метрик кода и решения о документировании](/docs/docs/domains/code-metrics-analysis#анализ-метрик-кода-и-решения-о-документировании) — Подсистема вычисляет для каждой сущности метрики размера, связности и побочных эффектов, обнаруживает тонкие обёртки и на основе логарифмического веса определяет роль документации и перечень включаемых Markdown-блоков.
* [Фасад сервиса Codelore](/docs/docs/domains/codelore-service-facade#фасад-сервиса-codelore) — Фасад CodeloreService — единая точка входа для всех операций с документацией Codelore.
* [Общие низкоуровневые утилиты](/docs/docs/domains/common-utils#общие-низкоуровневые-утилиты) — Предоставляет детерминированную идентификацию строк через SHA-256-хеширование и кроссплатформенную нормализацию путей с кодированием для URI — для всех вышележащих модулей проекта.
* [Визуализация графа файлов](/docs/docs/domains/dag-visualization#визуализация-графа-файлов) — Подсистема строит два представления направленного ациклического графа файлов: текстовое дерево с ASCII-стрелками для терминала и интерактивную HTML-страницу для браузера.
* [Согласование и валидация состояния документации](/docs/docs/domains/doc-state-consistency#согласование-и-валидация-состояния-документации) — Подсистема одновременно очищает DocState и находит ошибки ссылочной целостности и актуальности, но не добавляет новые секции.
* [Хранилище состояния документации](/docs/docs/domains/doc-state-storage#хранилище-состояния-документации) — Хранилище состояния документации получает готовое JSON-состояние документа и сохраняет его на диск вместе с Markdown-файлом и переводами, гарантируя целостность данных при сбоях за счёт атомарной записи (временный файл с последующим переименованием).
* [Перевод документации](/docs/docs/domains/doc-translation#перевод-документации) — Подсистема переводит канонические тела блоков документации на заданный язык через LLM-провайдера, гарантируя сохранность кодовых промежутков и отсутствие нетранслированного эха исходного текста.
* [Единый формат ошибок](/docs/docs/domains/error-handling#единый-формат-ошибок) — Предоставляет единый формат ошибок с машинно-читаемым кодом, на который опираются остальные подсистемы при взаимодействии с API-клиентами и UI.
* [Подготовка первичной документации](/docs/docs/domains/initial-docs-preparation#подготовка-первичной-документации) — По списку сущностей кода и области фильтрации определяет, для каких сущностей нужны новые страницы документации, и создаёт для них скелетные DocState с пустыми телами блоков и отпечатками, пропуская уже задокументированные сущности.
* [Хранилище индексов и анализа изменений](/docs/docs/domains/json-storage#хранилище-индексов-и-анализа-изменений) — Хранилище сохраняет индексные данные и результаты анализа изменений в JSON-файлы и загружает их обратно.
* [Валидация и факт-чекинг сгенерированной документации](/docs/docs/domains/llm-doc-validation#валидация-и-факт-чекинг-сгенерированной-документации) — Подсистема проверяет сгенерированную документацию в два этапа: структурная валидация отсеивает формальные нарушения вроде битых ссылок и превышения длины, а LLM-факт-чекинг сверяет утверждения в блоках с исходным кодом и документацией зависимостей.
* [Пайплайн генерации документации файлов](/docs/docs/domains/llm-generation-pipeline#пайплайн-генерации-документации-файлов) — Пайплайн генерирует документацию для группы изменившихся файлов за один прогон: разбивает исходный код на чанки с учётом лимитов LLM, формирует и отправляет запросы, парсит ответы и проверяет каждый блок на фактические противоречия с помощью LLM, исправляя нарушения в цикле.
* [Разбор JSON-ответов LLM с повтором запроса](/docs/docs/domains/llm-json-response-parsing#разбор-json-ответов-llm-с-повтором-запроса) — Подсистема даёт остальной системе надёжный способ получить структурированный JSON-объект из текстового ответа языковой модели.
* [Фабрика LLM-провайдера](/docs/docs/domains/llm-provider-factory#фабрика-llm-провайдера) — Фабрика создаёт настроенный ChatCompletionProvider: разрешает имя провайдера (по умолчанию из config.llm.provider), проверяет наличие конфигурации в config.llm.providers и при отсутствии выбрасывает CodeloreError с кодом UNKNOWN\_LLM\_PROVIDER.
* [Подготовка исходного контекста для LLM-верификации](/docs/docs/domains/llm-source-context-prep#подготовка-исходного-контекста-для-llm-верификации) — Подсистема готовит для LLM очищенный от комментариев исходный код и контекст объявлений типов, прямо используемых в секциях документации.
* [Рендеринг и локализация Markdown-документов](/docs/docs/domains/markdown-rendering#рендеринг-и-локализация-markdown-документов) — Подсистема превращает внутреннее состояние документа в готовый Markdown-файл с локализованными заголовками и цитатами об устаревших или непереведённых блоках.
* [MCP-сервер Codelore](/docs/docs/domains/mcp-server#mcp-сервер-codelore) — Поднимает MCP-сервер, который подключается к StdioServerTransport и обрабатывает запросы через stdin/stdout, делая ресурсы и инструменты документации Codelore доступными для внешних MCP-клиентов.
* [Конфигурация проекта](/docs/docs/domains/project-config#конфигурация-проекта) — Загружает и объединяет настройки проекта из `codelore.config.json` и `.env`-файла, а также выбирает локализованные термины для заданного языка и путей файлов.
* [Управление индексом проекта](/docs/docs/domains/project-index-manager#управление-индексом-проекта) — Предоставляет единую точку для получения актуального ProjectIndex, объединяющего код и документацию.
* [Построение runtime-контекста из литералов](/docs/docs/domains/runtime-context#построение-runtime-контекста-из-литералов) — Строит для сущности кода карту всех вхождений её строковых литералов в других сущностях проекта, отсеивая технические использования.
* [Применение перезаписей секций](/docs/docs/domains/section-rewrite-application#применение-перезаписей-секций) — Подсистема принимает запросы на перезапись секций сгенерированными блоками, группирует их по документу и вливает каждый блок в состояние секции: вычисляет отпечаток, обновляет тело, оценки и сбрасывает флаги устаревания, после чего обновляет метаданные секции и сохраняет документ.
* [Общие вспомогательные функции сервиса](/docs/docs/domains/service-helpers#общие-вспомогательные-функции-сервиса) — Предоставляет набор чистых утилит для типовых операций сервисного слоя: проверка пересечения диапазонов, дедупликация и сортировка массивов строк и сущностей, поиск первого дубликата, свёртка полных сущностей и секций документации в краткие представления, группировка по ключу, проверка идентификаторов блоков и нормализация ошибок.
* [Обнаружение устаревших блоков документации](/docs/docs/domains/stale-blocks-detection#обнаружение-устаревших-блоков-документации) — Выявляет устаревшие блоки документации: сравнивает сохранённые отпечатки с актуальным кодом и документацией зависимостей, находит блоки с удалёнными сущностями, блоки на неверном языке и ранее «похороненные».

## Зачем это нужно

Codelore — система автоматического документирования кодовых баз: строит индексы экспортированных сущностей, генерирует и обновляет Markdown-документацию через LLM-пайплайн, обнаруживает устаревшие блоки и применяет переводы. Остальная система получает через единый фасад CodeloreService сквозной API, чтобы не разбираться в индексации, генерации, отпечатках и файловом хранилище.

## Что делает

Система владеет полным жизненным циклом документации: от построения индекса кода и документации до рендеринга Markdown-файлов с локализованными заголовками и цитатами устаревших блоков. IndexManager параллельно собирает код- и док-индексы, CodeloreService оркестрирует подготовку скелетов новых секций, обнаружение устаревших блоков, двухфазный LLM-конвейер с верификацией фактов и применение перезаписей. Подсистема отпечатков вычисляет хеши блоков для сравнения с актуальным кодом, граф зависимостей разбирает unified diff и строит файловый граф с волнами генерации. Хранилище атомарно сохраняет JSON-состояния и Markdown, а подсистема перевода через LLM готовит локализованные версии блоков, отбрасывая дефектные. MCP-сервер предоставляет ресурсы и инструменты документации внешним клиентам.

## Кто и как использует

Запрос на генерацию документации проходит через CodeloreService, который сначала строит или обновляет индексы через IndexManager. Для новых сущностей prepareInitialDocs создаёт скелетные DocState с пустыми телами блоков. refreshStaleDocs через подсистему обнаружения устаревших блоков сравнивает отпечатки с актуальным кодом и документацией зависимостей, выявляет блоки с удалёнными сущностями и «похороненные» блоки, формирует план перезаписи. runPipelineForSections запускает двухфазный LLM-конвейер: пайплайн генерации разбивает исходный код на чанки, формирует запросы, парсит ответы и проверяет блоки на фактические противоречия с помощью LLM, исправляя нарушения в цикле. rewriteSections группирует перезаписи по документу, вливает каждый блок в состояние секции, вычисляет отпечаток, обновляет тело и сбрасывает флаги устаревания, после чего хранилище атомарно сохраняет JSON-состояние и рендерит Markdown с локализованными заголовками. translateScope для каждого настроенного языка запускает перевод блоков через LLM, проверяет целостность кодовых промежутков и отбрасывает дефектные переводы, затем сохраняет переведённые Markdown-файлы.

## Чего не делает

Система не проверяет схему конфигурации и не разрешает относительные пути при загрузке codelore.config.json — эта ответственность лежит на вызывающем коде. Она не управляет жизненным циклом LLM-провайдера и не обрабатывает ошибки провайдера выше фабрики. Валидация контента ограничена обнаружением фактических противоречий с исходным кодом и не включает логическую или стилистическую проверку. Отпечатки вычисляются только для owned-сущностей блока; если список owned пуст, возвращается undefined, что не позволяет отследить изменения для блоков без владельцев. Статус «похороненных» блоков не проверяется по коду повторно — система полагается на ранее сохранённую метку staleSince. При индексации файлы вне источниковых глобов игнорируются.
