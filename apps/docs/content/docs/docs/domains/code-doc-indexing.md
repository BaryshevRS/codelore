## Зачем это нужно

Подсистема строит два независимых индекса — код-индекс для экспортированных сущностей и док-индекс для секций документации — и выдаёт системе быстрый поиск по идентификатору, файлу и сущности без прямого обращения к файловой системе или хранилищу состояний. Код-индекс собирает идентификаторы, прямые зависимости и документационные метаданные для каждой сущности, док-индекс — обратные карты от файлов и сущностей к секциям документации.

## Что делает

Подсистема отвечает за актуальное состояние обоих индексов. Индекс кода строится обходом исходных файлов, попадающих под sourceGlobs и scope: для каждого экспортированного элемента фиксируется идентификатор, прямые зависимости и метаданные документации (вес и решение о документировании предоставляет анализатор метрик). Индекс документации опирается на состояния из DocStateStorage: все состояния загружаются, преобразуются в секции и индексируются по путям файлов и названиям сущностей с детерминированной сортировкой. Функция patchDocIndexPaths позволяет обновить индекс для заданных документов без полной перестройки: удаляет секции по переданным путям, очищая привязки в entityToSections, и добавляет секции из свежих состояний.

## От чего зависит

Подсистема делегирует вычисление веса сущности и решение о документировании анализатору метрик — эти данные попадают в документационные метаданные индекса кода и в поле weight секций документации. Для чтения состояний документации при построении и инкрементальном обновлении индекса использует хранилище DocStateStorage. Нормализацию путей и кодирование идентификаторов выполняет через низкоуровневые утилиты проекта. Не преобразует состояния в Markdown, не разрешает реэкспорты, не проверяет целостность связей — эти задачи лежат на вызывающей стороне или других подсистемах.

## Кто и как использует

При полной перестройке индекса кода buildCodeIndex принимает sourceGlobs и scope, обходит подходящие файлы и строит отображение файл→список сущностей с их атрибутами. При построении индекса документации buildDocIndex загружает все состояния через DocStateStorage, преобразует их в секции и наполняет обратные карты fileToSections и entityToSections, сортируя ключи для воспроизводимости. Инкрементальное обновление через patchDocIndexPaths: из принятого DocIndex удаляются секции, соответствующие переданным docPaths, и очищаются записи в entityToSections; затем для каждого пути загружается актуальное состояние, добавляются новые секции, сортируются списки затронутых сущностей и обновляется метка generatedAt.

## Чего не делает

Индексатор кода не прослеживает реэкспорты через `export * from`: зависимость считается с файлом реэкспорта, а не с фактическим источником. Неэкспортированные сущности и файлы вне sourceGlobs (если не попали в scope) игнорируются. Индексатор документации не проверяет целостность перекрёстных ссылок и не записывает изменения на диск. При инкрементальном обновлении сортируются только списки сущностей для затронутых документов — порядок в остальных сущностях не переопределяется. Разрешение зависимостей и вычисление документационных метаданных делегированы, подсистема не выполняет их самостоятельно.
