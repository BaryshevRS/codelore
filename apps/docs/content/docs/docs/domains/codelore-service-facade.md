## Зачем это нужно

Фасад CodeloreService — единая точка входа для всех операций с документацией Codelore. Он даёт остальной системе сквозной API, чтобы не работать с внутренними подсистемами напрямую, а клиентам — единообразно строить индексы, генерировать и обновлять Markdown-документы, анализировать изменения и выполнять валидацию.

## Что делает

Сервис оркестрирует полный жизненный цикл документации: инициирует построение индексов через IndexManager, подготавливает скелеты новых секций через prepareInitialDocs, управляет обнаружением устаревших блоков через refreshStaleDocs, вызывает двухфазный LLM-пайплайн через runPipelineForSections и применяет перезаписи через rewriteSections. Кэширует проектный контекст в projectContextCache и сбрасывает его при перестроении индекса. Предоставляет методы чтения: readDocSection рендерит секцию в Markdown, readCodeEntity добавляет исходный код сущности, readImpact возвращает влияние на другие сущности, readDocFile отдаёт сырое содержимое файла. Выполняет валидацию через validateDocs, которая перестраивает индекс и для каждой секции вызывает проверки владеемых сущностей, зависимостей, устаревших блоков и качества. translateScope обновляет переводы для всех настроенных языков, удаляя переводы для исключённых из конфигурации языков. Всю низкоуровневую работу — индексацию, хеширование, работу с диффами, запись на диск и форматирование Markdown — делегирует подсистемам.

## От чего зависит

Фасад опирается на IndexManager для построения и загрузки индексов, JsonStorage и DocStateStorage для персистентности. Для анализа изменений использует граф зависимостей: changedEntitiesFromDiff и changedEntitiesFromFiles определяют изменённые сущности, getAffectedSectionsForEntities вычисляет затронутые секции. Подготовку скелетов делегирует planFileLayout и docStateSectionForPlannedEntity, обнаружение устаревших блоков — buildRewriteContextBundle и applyTombstones, генерацию — createConfiguredProvider и generateFileGroup, применение перезаписей — groupRewritesByDoc и applyRewritesToDoc. Рендеринг Markdown выполняет renderSection, переводы — подсистема перевода, валидацию — validateOwnedEntities, validateDependencies, detectStaleBlocks и validateBlockQuality. Сам фасад не реализует логику индексации, вычисления отпечатков, построения графа зависимостей, трансляции диффов, атомарной записи на диск или форматирования Markdown — всё это остаётся за перечисленными подсистемами.

## Кто и как использует

Генерация документации для области: generateDocsForScope нормализует скоуп, через prepareInitialDocs создаёт скелетные секции для сущностей без документации, согласовывает состояния через reconcileScopedDocStates, запускает refreshStaleDocs в режиме tombstone для пометки устаревших блоков, собирает целевые блоки и передаёт их в runPipelineForSections. Пайплайн фильтрует секции по наличию в индексе, проверяет допустимость целевых блоков через collectAllowedBlocksForSection, запускает фазы propagating и terminal с ограничением параллелизма из config.llm.concurrency, собирает updatedSections, skipped и failed. rewriteSections группирует перезаписи по doc-файлу через groupRewritesByDoc, для каждого вызывает applyRewritesToDoc, затем обновляет doc-индекс через patchDocIndexForDocs. translateScope завершает цикл: фильтрует секции по скоупу, собирает уникальные пути документов, удаляет переводы для исключённых языков и переводит блоки для каждого настроенного языка. Анализ изменений: analyzeChange при отсутствии diff и changedFiles читает git-diff, определяет изменённые сущности, вычисляет затронутые секции и сохраняет результат; readChange извлекает запись по идентификатору. Чтение: readDocSection разрешает секцию, загружает состояние и рендерит в Markdown; readCodeEntity ищет сущность в индексе и добавляет исходный код через readEntityCode; readImpact вызывает getImpactForEntity; readDocFile читает файл относительно config.rootDir.

## Чего не делает

Фасад не валидирует конфигурацию проекта и не разрешает относительные пути — это зона конфигурационной подсистемы. readDocFile и readCodeEntity не проверяют принадлежность файла документированному проекту: readDocFile читает произвольный текст по пути относительно config.rootDir, readCodeEntity ищет сущность только в индексе. translateScope немедленно завершается, если config.docs.translations пуст. Кэш проектного контекста сбрасывается только при перестроении индекса через колбэк в IndexManager, поэтому изменения внешних файлов не будут замечены без явного вызова rebuildIndexes. Сервис не гарантирует атомарность записи — она обеспечивается DocStateStorage. readChange не валидирует содержимое записи ChangeAnalysis, доверяя хранилищу. rewriteSections выбрасывает ошибку при дубликатах секций во входных данных.
