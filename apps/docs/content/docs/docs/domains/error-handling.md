## Зачем это нужно

Предоставляет единый формат ошибок с машинно-читаемым кодом, на который опираются остальные подсистемы при взаимодействии с API-клиентами и UI. Класс CodeloreError фиксирует поля code (тип CodeloreErrorCode) и details, а функция toCodeloreErrorPayload превращает любое исключение в сериализуемый объект CodeloreErrorPayload — это гарантирует, что наружу уходит предсказуемая структура.

## Что делает

Определяет тип ошибки CodeloreError с публичными полями code (из перечисления CodeloreErrorCode) и details. Предоставляет утилиту toCodeloreErrorPayload, которая не модифицирует исходную ошибку и не выполняет логирование, а только возвращает готовый payload. Позволяет другому коду выбрасывать ошибки с осмысленным кодом, не думая о формате сериализации.

## От чего зависит

Не зависит от внешних библиотек — использует только стандартный класс Error. Осознанно не берёт на себя сериализацию, логирование и форматирование сообщений для конечного пользователя; эти задачи возложены на потребителей payload'а.

## Кто и как использует

Любое исключение передаётся в toCodeloreErrorPayload. Если ошибка — экземпляр CodeloreError, извлекаются поля code и details. Иначе функция формирует payload с code = INTERNAL\_ERROR и сообщением из error.message. Возвращаемый объект CodeloreErrorPayload готов к JSON-сериализации.

## Чего не делает

Не управляет HTTP-статусами, локализацией сообщений и фильтрацией чувствительных деталей — это зона ответственности вызывающего кода. Ошибки, не являющиеся CodeloreError, всегда получают код INTERNAL\_ERROR; чтобы получить другой код, необходимо выбросить экземпляр CodeloreError с нужным значением.
