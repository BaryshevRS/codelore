## Состав

* [diff](/docs/src/graph/diff) — Преобразует строку unified diff в структурированный список файлов с указанием затронутых диапазонов строк для последующего анализа изменений в проекте.
* [file-dag](/docs/src/graph/file-dag#file-dagts) — Превращает индекс сущностей проекта в файловый граф зависимостей и раскладывает выбранные файлы по волнам генерации, где каждая волна содержит группы файлов, которые можно документировать одновременно, потому что все их зависимости лежат в более нижних волнах.
* [impact](/docs/src/graph/impact) — Вычисляет множество секций, затронутых изменением переданных сущностей, объединяя прямое и транзитивное влияние.

**Используется в:** [Фасад сервиса Codelore](/docs/docs/domains/codelore-service-facade#фасад-сервиса-codelore) · [Визуализация графа файлов](/docs/docs/domains/dag-visualization#визуализация-графа-файлов) · [Пайплайн генерации документации файлов](/docs/docs/domains/llm-generation-pipeline#пайплайн-генерации-документации-файлов)

## Зачем это нужно

Преобразует унифицированный diff в структурированные данные об изменениях, строит по сущностному индексу файловый граф зависимостей с волнами генерации и вычисляет затронутые секции документации по переданным именам сущностей. Позволяет генератору документации пересобирать только изменившиеся фрагменты в порядке снизу вверх.

## Что делает

Парсит unified diff в список изменённых файлов с ханками и диапазонами строк. По сущностному индексу строит файловый граф зависимостей: каждому файлу сопоставляет множество файлов-зависимостей, отбрасывая самоциклы и отсутствующие в индексе файлы. Находит сильно связные компоненты итеративным алгоритмом Тарьяна, затем назначает каждой компоненте уровень волны как максимум из уровней её зависимостей плюс один. Группирует компоненты одного уровня в детерминированные волны. По списку имён сущностей находит секции, владеющие ими или зависящие от них, и рекурсивно расширяет множество транзитивными зависимыми секциями с сохранением минимального порядка.

## От чего зависит

Принимает на вход строку унифицированного диффа и внешний индекс сущностей, который предоставляет связи владения и зависимости (`owns`/`depends`) и отображение файлов на сущности. Не обращается к файловой системе, не разбирает исходный код напрямую и не генерирует документацию — возвращает только идентификаторы затронутых секций с порядком обработки и группы файлов по волнам.

## Кто и как использует

Клиент передаёт unified diff в parseUnifiedDiff и получает список изменённых файлов с ханками и номерами строк. Затем клиент самостоятельно (вне подсистемы) сопоставляет строки с сущностями индекса и вызывает getAffectedSectionsForEntities, передавая имена сущностей и индекс; функция вычисляет прямо затронутые и транзитивно зависимые секции, возвращая отсортированный список. Независимо от диффа клиент может запросить волны генерации для любого набора файлов: generationWaves строит файловый DAG через buildFileDag, фильтрует присутствующие в графе файлы, находит SCC, распределяет по волнам и выдаёт группы файлов, готовые к документированию снизу вверх.

## Чего не делает

Парсер ожидает строгий унифицированный формат diff, обрабатывает файлы по одному и не поддерживает многородительские или нестандартные диффы. Файловый DAG игнорирует сущности, отсутствующие в индексе, и зависимости внутри одного файла, что может скрыть часть связей. Все файлы в сильно связной компоненте попадают в одну волну без учёта внутренней структуры, ограничивая параллелизм. Анализ влияния оперирует только явно переданными именами сущностей; он не определяет изменённые сущности по диффу и не проверяет семантику изменений. Индекс сущностей должен быть актуален, иначе результаты неверны.
