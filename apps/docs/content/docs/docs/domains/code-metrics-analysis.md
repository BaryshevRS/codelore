## Состав

* [block-inclusion](/docs/src/analysis/block-inclusion) — Решает, какие блоки Markdown-секции включать в финальную документацию сущности, на основе метрик и конфигурации.
* [class-cohesion](/docs/src/analysis/class-cohesion) — Вычисляет метрики связности классов для документационного индекса.
* [decision-pass](/docs/src/analysis/decision-pass) — Определяет роль документации для каждой сущности кода на основе метрик, связности классов и обнаружения обёрток.
* [entity-metrics](/docs/src/analysis/entity-metrics) — Точка входа для расчёта метрик всех сущностей код-индекса.
* [wrapper-detector](/docs/src/analysis/wrapper-detector) — Определяет, какие приватные методы классов полностью инкапсулированы тонкой публичной обёрткой, для последующего исключения из обязательных блоков документации.

**Зависит от:** [Общие низкоуровневые утилиты](/docs/docs/domains/common-utils#общие-низкоуровневые-утилиты)
**Используется в:** [Индексация кода и документации](/docs/docs/domains/code-doc-indexing#индексация-кода-и-документации)

## Зачем это нужно

Подсистема вычисляет для каждой сущности метрики размера, связности и побочных эффектов, обнаруживает тонкие обёртки и на основе логарифмического веса определяет роль документации и перечень включаемых Markdown-блоков. Остальная система получает готовые решения о том, какую документацию генерировать для каждой сущности, без повторного анализа.

## Что делает

Владеет полным конвейером от получения индекса кода до выдачи решений о блоках. computeEntityMetrics делегирует подсчёт операторов, фильтрацию прямых использований и статический поиск побочных эффектов утилитам countStatements, effectiveDirectUsages и hasSideEffects. analyzeClassCohesion измеряет связность классов через пересечение полей, detectPrivateWrappers находит приватные методы, которые являются тонкими обёртками. Затем decideDocumentationRoles, делегируя вычисление роли функции decideEntityRole, получает вес через calculateWeight по логарифмической формуле, назначает роль, а determineBlockInclusion выбирает блоки по метрикам и конфигурации.

## Кто и как использует

Входной индекс подаётся в computeEntityMetrics, которая делегирует подсчёт операторов (countStatements), фильтрацию прямых использований (effectiveDirectUsages) и проверку обращений к process.env (hasSideEffects). Затем analyzeClassCohesion для каждого класса определяет overlap полей, а detectPrivateWrappers находит приватные методы-обёртки, вызывающие ровно один другой метод. Полученные метрики и результаты анализа передаются в decideDocumentationRoles, которая делегирует назначение роли функции decideEntityRole, а calculateWeight объединяет метрики (при необходимости с приватным методом-якорем) и вычисляет вес по логарифмической шкале. Наконец, determineBlockInclusion использует метрики и конфигурацию, чтобы определить, какие блоки включить.

## Чего не делает

Не обрабатывает динамически порождаемый код, косвенные вызовы (call/apply) и перегрузки методов. Побочные эффекты детектируются только по обращениям к process.env; присваивания полям других объектов игнорируются. Класс без методов считается несвязным (fieldOverlap=0). Обнаружение обёрток работает исключительно для приватных методов классов. In-degree вычисляется без транзитивных использований. Вес не учитывает историю изменений, а конфигурация блоков задаётся внешним кодом вне подсистемы.
