## Зачем это нужно

Фабрика конфигурации, объединяющая настройки из `codelore.config.json` с дефолтами.

## Что делает

* Не валидирует схему JSON — `JSON.parse` может бросить синтаксическую ошибку, которая не перехватывается.
* Не управляет временем жизни конфигурации — возвращает новый объект при каждом вызове.
* Не разрешает относительные пути внутри конфига (например, `indexDir`) — оставляет как есть, разрешение на вызывающей стороне.

## На что можно положиться

* Возвращаемый объект всегда содержит поле `rootDir`, равное переданному аргументу.
* Все поля верхнего уровня (`sourceGlobs`, `docGlobs`, `excludeGlobs`, `indexDir`, `docs`, `thresholds`, `blockInclusion`, `llm`) гарантированно присутствуют в результате — при отсутствии в файле используются дефолтные значения.
* Поле `docs.language` может отсутствовать (`undefined`), так как не имеет дефолтного значения.
* Если ни один конфигурационный файл не существует, возвращается конфигурация с полными дефолтами без вызова валидации схемы.
* Значение `concurrency` гарантированно является целым числом >= 1, если передан валидный number, иначе используется дефолтное значение 50.

## От чего зависит

* `existsSync`, `readFileSync` (`node:fs`) — синхронное чтение файла конфигурации.
* `join` (`node:path`) — склеивание `rootDir` с именем файла.
* `DEFAULT_BLOCK_HEADINGS_EN` (`src/markdown/block-ids.js`) — значения заголовков блоков по умолчанию для английского языка.
* Типы: `BlockInclusionConfig`, `CodeloreConfig`, `DocsConfig`, `LlmConfig` (`src/types.js`) — структуры данных.

## Кто и как использует

Вызывается в конструкторе [`CodeloreService`](/docs/src/service/codelore-service#codeloreservice) (`src/service/codelore-service.ts`) для инициализации поля `config`. При отсутствии обоих конфигурационных файлов возвращает полные дефолты без валидации схемы.

## Чего не делает

* Конфигурация загружается только из двух файлов: `codelore.config.json` и `<indexDir>/config.json`. Нет поддержки нескольких конфигов или наследования.
* Синхронное чтение (`readFileSync`) — неблокирующие альтернативы не рассматриваются, что может повлиять на производительность при большом количестве вызовов.

## Как менять и что проверять

* При отсутствии обоих конфигурационных файлов возвращаются полные дефолты без вызова валидации схемы. Если требуется валидировать дефолты, нужно убрать этот ранний возврат.
* Значение `concurrency` гарантированно является целым числом >= 1 благодаря проверке и `Math.floor`. Если требуется допускать дробные значения, нужно убрать `Math.floor`.

## loadDotEnv

### Зачем это нужно

Загрузка переменных окружения из `.env`-файла для конфигурации проекта.

### Что делает

* Проверяет существование `.env`-файла в корне проекта.
* Если файл существует, загружает его с помощью `process.loadEnvFile`.
* Не выполняет никаких действий при отсутствии файла.

### На что можно положиться

* Вызов не бросает исключений, если `.env` отсутствует — функция выполняет ранний возврат.
* Загружается только файл `.env` в переданной директории, без поиска по родительским директориям.

### Кто и как использует

Вызывается однократно при старте CLI (`src/bin/codelore.ts`). Загружает переменные окружения из `.env`-файла в корне проекта, если он существует.

### Чего не делает

Загружается только файл с именем `.env` в переданной директории — нет поддержки `.env.local`, `.env.production` или поиска по родительским директориям. Ограничение реализовано фиксированным именем файла `".env"` и использованием `join(rootDir, ".env")`.

### Как менять и что проверять

* Имя загружаемого файла зафиксировано как `".env"` в вызове `join(rootDir, ".env")`. Если потребуется поддержка других файлов (например, `.env.local`), потребуется изменить эту строку.
* Ранний возврат при отсутствии файла реализован через `if (!existsSync(envPath)) { return; }`. Если требуется бросать исключение при отсутствии файла, этот guard нужно удалить.

## resolveTerms

### Зачем это нужно

Выбор терминов для заданного языка из `docs.terms` с фильтрацией по matching-шаблонам путей файлов.

### Что делает

* Обходит группы терминов из `docs.terms` и пропускает группу, если её `match` задан и ни один из переданных путей не соответствует шаблону.
* Собирает термины для указанного языка из каждой оставшейся группы, удаляет дубликаты и пустые строки, сохраняя порядок групп.

### На что можно положиться

* Возвращаемый массив не содержит дубликатов и пустых строк.
* Порядок терминов соответствует порядку групп в конфигурации и порядку внутри каждой группы.

### Кто и как использует

Вызывается из [`generateFileGroup`](/docs/src/llm/file-pipeline#generatefilegroup) (`src/llm/file-pipeline.ts`) для получения списка терминов, релевантных для набора файлов. Передаются пути файлов, для которых собираются термины.

### Чего не делает

Не поддерживает отрицательные шаблоны `match` (например, `!**/test/**`), так как используемая функция не инвертирует результат.

### Как менять и что проверять

* Дубликаты удаляются через `Set` (`seen`), что гарантирует уникальность терминов в возвращаемом массиве. Если требуется сохранить дубликаты, нужно удалить `seen` и связанную проверку `!seen.has(trimmed)`.
* Пустые строки отфильтровываются условием `if (trimmed && ...)`. Если требуется включать пустые строки, нужно убрать проверку `trimmed`.
