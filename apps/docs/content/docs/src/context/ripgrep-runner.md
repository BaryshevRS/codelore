## Зачем это нужно

Поиск точных вхождений строки в исходных файлах TypeScript/JavaScript проекта через ripgrep.

## Что делает

* Не обрабатывает регулярные выражения — только точное совпадение (`--fixed-strings`).
* Не выполняет AST-фильтрацию — возвращает все совпадения, найденные ripgrep.
* Не определяет контекст использования строки — только факт совпадения.
* Не изменяет файлы или проект.

## На что можно положиться

* Для непустой строки всегда возвращает массив (может быть пустым), никогда не бросает исключение при коде завершения 0 или 1.
* Возвращает только совпадения из файлов с расширениями `.ts` и `.js`, исключая `node_modules`, `dist`, `build`, `.codelore`, `coverage`.
* Колонка в хите — 1-based (первый символ = 1).
* Пустая строка возвращает пустой массив без запуска внешнего процесса.

## От чего зависит

* `@vscode/ripgrep` — предоставляет путь к исполняемому файлу ripgrep (`rgPath`).
* `node:child_process` — запуск ripgrep как внешнего процесса.

## Кто и как использует

Вызывается из [`buildRuntimeContext`](/docs/src/context/runtime-context-builder#buildruntimecontext) (`src/context/runtime-context-builder.ts`) для каждого уникального литерала, извлечённого из исходного кода целевой сущности. Передаёт `rootDir` проекта и исключает сам файл сущности из поиска. Возвращённые хиты далее обрабатываются `resolveHitsForLiteral`.

## Чего не делает

* Ищет только в `.ts` и `.js` — не покрывает `.tsx`, `.json`, `.md`.
* Не поддерживает поиск без учёта регистра (по умолчанию регистрозависимый).
* Не обрабатывает символические ссылки (поведение ripgrep по умолчанию).

## Как менять и что проверять

1. Если изменить `BASE_GLOBS` или `BASE_EXCLUDES`, может измениться покрытие поиска — проверить, что вызывающий ([`buildRuntimeContext`](/docs/src/context/runtime-context-builder#buildruntimecontext)) ожидает именно такой набор файлов.
2. Если изменить парсинг JSON-вывода ripgrep (например, перестать обрабатывать `submatches`), сломается структура хитов — обновить типы `RipgrepHit` и все места, использующие эти поля.
3. Если изменить обработку кода завершения (код 1 перестанет означать «нет совпадений»), сломается контракт — обновить [`buildRuntimeContext`](/docs/src/context/runtime-context-builder#buildruntimecontext) и его док-секцию.
