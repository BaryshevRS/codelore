## Зачем это нужно

Генерирует текстовое ASCII-представление DAG файлов с разбивкой по волнам генерации, статусом документирования и стрелками зависимостей.

## Что делает

* Не генерирует HTML-страницу — эта задача передана другой функции.
* Не управляет записью в файл или stdout — возвращает строку; вызывающий сам решает, куда её вывести.
* Не выполняет фильтрацию файлов — делегирует её `collectNodes`, которая учитывает `input.paths` и транзитивные зависимости.
* Не поддерживает интерактивность — только статическое текстовое дерево.

## На что можно положиться

* Возвращает строку, начинающуюся с «Generation pyramid …».
* Включает все файлы из видимого подмножества графа (scope + их зависимости).
* Метки статуса строго «✓» (documented), «~» (stale), «!» (sections=0 но documentable), «∅» (sections=0 и не documentable); стрелки для зависимостей показывают ту же метку.
* Волны сортируются по возрастанию номера; файлы внутри волны — лексикографически по пути.
* Не бросает исключений для любого допустимого `GraphRenderInput`.

## От чего зависит

* Строит DAG файлов по прямым зависимостям (из [`src/graph/file-dag.ts`](/docs/src/graph/file-dag#file-dagts)).
* Разбивает файлы на волны генерации, учитывая SCC (из [`src/graph/file-dag.ts`](/docs/src/graph/file-dag#file-dagts)).

## Кто и как использует

Вызывается из `run-cli.ts` для построения текстового дерева зависимостей. `collectNodes` использует DAG и результаты разбиения на волны, затем результаты группируются по волнам и форматируются в ASCII-дерево. Возвращаемая строка выводится в stdout.

## Чего не делает

* Выводит только прямые зависимости из DAG, полученные через `dag.get(file)`; транзитивные цепочки не отображаются.
* Не реализована пагинация — при большом количестве файлов вывод может быть громоздким (нет ограничения размера).
* Волны и состав групп зависят от логики разбиения на волны; изменение этого модуля может изменить отображение, но функция не проверяет согласованность.

## Как менять и что проверять

* Изменение меток в `statusMark` (функция `statusMark(node: FileNode): string`) нарушит согласованность с `statusClass` и HTML-рендерингом; обе функции должны быть синхронизированы.
* Изменение сортировки волн (`[...byWave.keys()].sort((left, right) => left - right)`) или файлов внутри волны (`node.deps.sort()`) изменит порядок вывода, что может нарушить тесты, ожидающие конкретный порядок.

## renderGraphHtml

### Зачем это нужно

Генерирует интерактивную HTML-страницу с визуализацией DAG файлов с разбивкой по волнам генерации, цветовой индикацией статуса документирования и поддержкой кликов.

### Что делает

* Не сохраняет страницу в файл — возвращает строку HTML; вызывающий отвечает за запись.
* Не загружает Cytoscape локально — использует CDN `unpkg.com` с фиксированной версией `3.30.4`.
* Не вычисляет DAG — делегирует `collectNodes`, а волны группирует вручную через `byWave`.
* Не поддерживает поиск, фильтрацию или панорамирование за пределами встроенного зума Cytoscape.

### На что можно положиться

* Возвращает валидный HTML5 документ.
* Cytoscape загружается по URL `https://unpkg.com/cytoscape@3.30.4/dist/cytoscape.min.js`.
* Позиции узлов детерминированы: `x` вычисляется по индексу в строке волны, `y` — по номеру волны.
* Рёбра направлены от файла к его зависимости (стрелка на конце).
* Цвета фона узлов соответствуют статусу: `#d3f9d8` (documented), `#fff3bf` (stale), `#ffe3e3` (pending), `#f8f9fa` (excluded).
* При клике на узел подсвечивается его соседство, остальные затемняются; повторный клик на фон возвращает исходное состояние.

### От чего зависит

* Построение DAG файлов (из [`src/graph/file-dag.ts`](/docs/src/graph/file-dag#file-dagts)).
* Разбиение файлов на волны для позиционирования узлов (из [`src/graph/file-dag.ts`](/docs/src/graph/file-dag#file-dagts)).
* Cytoscape.js (внешний CDN) — рендеринг интерактивного графа.

### Кто и как использует

Вызывается из `run-cli.ts` для генерации HTML-страницы графа. `collectNodes` получает файлы и волны, затем `renderGraphHtml` вручную группирует по волнам, вычисляет позиции узлов и формирует JSON-данные, которые встраиваются в шаблон `htmlPage`. Возвращаемая строка может быть записана в файл или выведена на stdout.

### Чего не делает

* Требует сетевого доступа для загрузки Cytoscape с CDN по фиксированному URL `https://unpkg.com/cytoscape@3.30.4/dist/cytoscape.min.js`; без сети страница не работает.
* При большом количестве файлов узлы могут накладываться: расстояние по X фиксировано (`* 230`), не адаптируется под количество узлов в строке.
* JSON-данные вставляются через строковую интерполяцию с заменой `</` на `<\/`; это может сломаться при других специальных последовательностях.

### Как менять и что проверять

* Изменение формулы позиционирования (`x: (column - (rowMates.length - 1) / 2) * 230`, `y: (maxWave - node.wave) * 170`) изменит расположение узлов; тесты, основанные на фиксированных положениях, сломаются.
* Изменение цветов в объекте `colors` (константа в `htmlPage`) требует синхронизации с CSS-легендой в том же шаблоне; добавление нового статуса требует обновления обоих мест.
