## Зачем это нужно

Преобразует строку unified diff в структурированный список файлов с указанием затронутых диапазонов строк для последующего анализа изменений в проекте.

## Что делает

* Парсит заголовки файлов (`diff --git`) и плюс-заголовки (`+++ b/...`), извлекая пути файлов.
* Извлекает заголовки ханков (`@@ ... @@`) и вычисляет начальную строку и диапазон для каждого ханка.
* Собирает результаты в массив объектов `DiffFileChange`, группируя ханки по файлу.

## На что можно положиться

* Каждый элемент содержит path и массив ranges, где каждый range соответствует одному заголовку ханка, а его startLine и endLine вычислены согласно unified diff формату.
* Функция игнорирует любые строки diff, не соответствующие трём известным паттернам (заголовок файла, заголовок +++, заголовок ханка), и продолжает обработку без ошибок.

## Кто и как использует

Функция вызывается из двух методов сервиса CodeloreService. В CodeloreService.analyzeChange она преобразует дифф-строку в список путей файлов, когда передан параметр diff, или когда diff прочитан через readGitDiff; полученные пути передаются в changedEntitiesFromDiff. В CodeloreService.changedEntitiesFromDiff она вызывается напрямую для итерации по структурированным изменениям и сопоставления диапазонов строк с сущностями кода.

## Как менять и что проверять

Функция поддерживает два ключевых инварианта. 1. Каждый объект в массиве ranges соответствует ровно одному разобранному заголовку ханка. Это обеспечивается проверкой `if (hunk && current) { current.ranges.push(hunk); }`, которая выполняется только при успешном парсинге ханка и наличии текущего файла. Тест, проверяющий это поведение, не представлен в текущем контексте. 2. Строки, не соответствующие ни одному из трёх паттернов, игнорируются и не прерывают обработку. Это обеспечено последовательностью условных операторов `if (filePath)`, `if (plusPath)`, `if (hunk && current)` без ветки `else`, так что неподходящие строки не имеют эффекта. Тест не указан.
