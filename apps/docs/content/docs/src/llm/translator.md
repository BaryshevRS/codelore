## Зачем это нужно

Создаёт уникальный строковый ключ для пары идентификаторов раздела и блока, чтобы использовать его в качестве ключа ассоциативного массива при фингерпринтинге переводов.

## Что делает

* Конкатенирует sectionId, нулевой символ и blockId в одну строку.

## На что можно положиться

Возвращаемый ключ детерминирован: одинаковые пара (sectionId, blockId) всегда дают одинаковую строку.

## От чего зависит

Не использует внешние модули; зависит только от своих строковых аргументов sectionId и blockId.

## Кто и как использует

Вызывается внутри translateBlocks при построении sourceByKey (input.blocks.map(...)) и при разборе ответа LLM в parseTranslateResponse для формирования ключей TranslatedBlocks. Также вызывается из CodeloreService.translateDoc как translationBlockKey(entry.sectionId, entry.blockId) для извлечения перевода конкретного блока из результата translateBlocks.

## Чего не делает

Не проверяет корректность sectionId или blockId — при передаче некорректных значений (например, содержащих нулевой символ) может дать неоднозначный ключ.

## translateBlocks

### Зачем это нужно

Переводит канонические тела блоков документации на заданный язык с использованием LLM-провайдера, обеспечивая сохранение кодовых промежутков (backtick-спанов) и отсутствие нетранслированного эха.

### Что делает

* Строит запрос к LLM через buildTranslateRequest, передавая все блоки входного документа.
* Извлекает ответ через completeAndParseTranslation, поддерживая повторные попытки при невалидном JSON (ошибка INVALID\_LLM\_RESPONSE).
* Выявляет нарушения через collectViolations — отсутствие блока в ответе, несовпадение кодовых промежутков или нетранслированный текст — и при их наличии отправляет ремонтный запрос buildRepairRequest только для проблемных блоков.
* Применяет финальную проверку blockViolation и возвращает карту только тех блоков, которые её прошли; блоки, не прошедшие проверку или отсутствующие после ремонта, отбрасываются.

### На что можно положиться

* Выходная карта содержит только блоки, для которых blockViolation(canonical, translation) вернула undefined.
* Каждый перевод сохраняет все backtick-спаны исходного текста и не может быть точной копией исходного прозы.
* Если ответ LLM содержит невалидный JSON, выбрасывается исключение CodeloreError с кодом "INVALID\_LLM\_RESPONSE", если исчерпаны повторные попытки в completeAndParseTranslation.
* При пустом input.blocks возвращается пустая карта без вызова LLM.

### От чего зависит

Зависит от файла [src/errors.ts](/docs/src/errors) для обработки ошибок невалидного JSON и от файла [src/llm/json.ts](/docs/src/llm/json) для парсинга ответа LLM. Провайдер ChatCompletionProvider передаётся извне; внутренние функции buildTranslateRequest, buildRepairRequest, blockViolation, collectViolations, completeAndParseTranslation определены в том же файле.

### Кто и как использует

Вызывается из CodeloreService.translateDoc: сервис собирает список блоков, требующих перевода (pending), и передаёт их с языком, правилами письма и предпочтительными терминами. Функция строит первичный запрос через buildTranslateRequest, отправляет его провайдеру через completeAndParseTranslation, парсит ответ, выявляет нарушения через collectViolations, при их наличии отправляет ремонтный запрос buildRepairRequest только для проблемных блоков, и возвращает карту принятых переводов (accepted). Сервис затем сохраняет переводы в состоянии документа и инициирует рендеринг.

### Чего не делает

Ограничена одним ремонтным раундом (violations.size > 0 запускает ровно один повторный запрос). Транспортные ошибки провайдера не повторяются внутри функции — они пробрасываются наружу (провайдер обрабатывает их сам). Перевод проверяется только на сохранение backtick-спанов и отсутствие эха, а не на семантическую верность.

### Как менять и что проверять

* Пустой список блоков не вызывает LLM: конструкция `if (input.blocks.length === 0) { return new Map(); }`.
* Повторная попытка запускается только при ошибке INVALID\_LLM\_RESPONSE: условие `if (attempt >= maxRetries || !(error instanceof CodeloreError && error.code === "INVALID_LLM_RESPONSE")) { throw error; }`.

## translationNeedsWork

### Зачем это нужно

Проверяет, содержит ли сохранённый перевод дефект, требующий перевода заново — несовпадение кодовых промежутков или нетранслированный эхо исходного текста.

### Что делает

* Делегирует проверку внутренней функции blockViolation, передавая source и translation.
* Возвращает true при любом нарушении контракта перевода, иначе false.

### На что можно положиться

Всегда возвращает false, если translation проходит все проверки blockViolation, и true в противном случае. Никогда не выбрасывает исключений.

### От чего зависит

Не зависит от внешних модулей; вызывает внутреннюю функцию blockViolation.

### Кто и как использует

Импортируется в [src/service/codelore-service.ts](/docs/src/service/codelore-service) и используется в процедуре обновления состояния документа для определения, нужно ли переводить блок заново, даже если его фингерпринт не изменился. Вызов translationNeedsWork(source, translation) позволяет отбросить дефектный перевод при следующей волне перевода.

### Чего не делает

Наследует ограничения blockViolation: не проверяет семантическую эквивалентность, только отсутствие или лишние код-спаны (порядок не учитывается).
